# KiCad 10 vendor part import: vendor package formats and KiCad 10 file-format changes

Research date: 2026-10-18. KiCad 10.0.0 was released March 2026; the 10.0.x branch is at least 10.0.6 (Aug 2026). Local machine has KiCad 9.0 installed (no 10.0 config dir, no `C:\Program Files\KiCad\10.0`), so nothing about KiCad 10 was verified on the user's machine. "Local sample" below means the Ultra Librarian zip in `C:\Git_Repo_Clones\Kicad_Libraries-importer\downloaded_examples\ul_CSD85301Q2.zip`, which I extracted and read (primary evidence).

## Q1. What do Ultra Librarian, SnapEDA/SnapMagic and SamacSys/CSE KiCad downloads contain, and what are their known defects?

### Takeaway
Ultra Librarian is the only vendor I could verify from a real file (the local sample): a zip with a KiCad v6-era `.kicad_sym` (version 20211014), a `.pretty` folder, a separate STEP and no `(model ...)` line, a Footprint property without a library nickname, and all pins typed `unspecified`. SnapEDA and SamacSys are documented only through help pages and forum posts: a zip with one `.kicad_sym` and one `.kicad_mod` (SnapEDA), and legacy/`.kicad_sym` libraries via Library Loader (SamacSys). I found no real sample for either, so their internals remain unverified.

### Cited Findings

**Ultra Librarian (verified from the local sample `ul_CSD85301Q2.zip`)**
- Zip layout: `DLV0006A.stp` (3D model, STEP AP214-style text, "CREO PARAMETRIC" header), `ImportGuides.html`, `readme.txt` (generic UL notes about drill sizes and slots), `KiCADv6/<timestamp>.kicad_sym` (name is the download timestamp, here `2026-10-18_09-12-49.kicad_sym`, not the part number), `KiCADv6/footprints.pretty/DQK0006B.kicad_mod`, `KiCADv6/ImportGuide.html`. The STEP sits at zip root, outside the `KiCADv6/` folder. — local file `downloaded_examples/ul_CSD85301Q2.zip`
- STEP name `DLV0006A` differs from footprint name `DQK0006B` (the TI package drawing code), so the model cannot be matched to the footprint by file stem. — local sample
- Symbol header is `(kicad_symbol_lib (version 20211014) (generator kicad_symbol_editor)` on one line with a bare (unquoted) generator. This is KiCad 6.0-era format. The `kicad_symbol_editor` generator name is one the KiCad dev docs ask third-party tools not to use. — local sample; [KiCad dev docs, symbol library format](https://dev-docs.kicad.org/en/file-formats/sexpr-symbol-lib/index.html)
- Symbol properties use the old `(id N)` token, e.g. `(property "Footprint" "DQK0006B" (id 2) (at 0 0 0) (effects (font (size 1.27 1.27) italic) hide))`, with `hide` as a bare flag inside `effects` (pre-20241004 style). Extra properties: `ki_keywords`, `ki_locked` (empty), `ki_fp_filters`. — local sample
- The Footprint property value is the bare footprint name `DQK0006B`, with no `Library:` nickname. — local sample
- Datasheet field is populated with a URL (`https://www.ti.com/lit/gpn/csd85301q2`). — local sample
- Multi-unit symbol: sub-symbols `CSD85301Q2_1_1` and `CSD85301Q2_2_1` (two units, one per FET); 8 pins total, all `(pin unspecified line ...)` (electrical type unspecified), pin names like "S1", "G1", "D1" (duplicate names across pins, e.g. "D1" twice). — local sample
- Footprint header is `(footprint "DQK0006B" (version 20211014) (generator pcbnew)` (KiCad 6.0 format): uses `fp_text reference/value/user`, `fp_line ... (width 0.1)`, `fp_circle ... (fill none)`, no `(property ...)` tokens, no `(model ...)` token at all, no uuid/tstamp. Pads are numbered strings `"1"`..`"8"`, coordinates have float noise (e.g. `-0.974999`, `1.000001`). — local sample
- Files are LF-terminated in the symbol (no CR found); the HTML guides use CRLF. — local sample
- UL's own KiCad 6.0+ help describes importing a `[date].lib` symbol file, a `.pretty` folder and a separate STEP, then loading the STEP manually in the Footprint Properties 3D Models tab. The doc text predates the `.kicad_sym` export (the local sample proves `.kicad_sym` is now what the KiCad v6 option produces). — [Ultra Librarian KiCad 6.0+ help](https://app.ultralibrarian.com/content/help/kicad-6_0.htm)
- Forum reports of UL problems: Footprint field must be `[library nickname]:[footprint name]`, otherwise the symbol is not valid and netlist import fails with "footprint not found in any libraries in the footprint library table"; one helper called a UL connector symbol "really bad" with odd pin numbering. — [KiCad forum: Help importing part from Ultra Librarian](https://forum.kicad.info/t/help-importing-part-from-ultra-librarian/21847)
- Another forum thread attributes "invalid footprint" in the schematic editor to a Footprint property that does not match the footprint filename or contains a slash. — [KiCad forum: How to install a symbol & footprint that I downloaded](https://forum.kicad.info/t/how-to-install-a-symbol-footprint-that-i-downloaded/62881/12)

**SnapEDA / SnapMagic (documentation only, no real sample available)**
- Official import page: the KiCad zip "holds a .kicad_sym symbol file and a .kicad_mod footprint file." Footprint import means pointing KiCad at the folder containing the `.kicad_mod`; the page says to rename the folder to match the part if the path name differs. It does not describe footprint-link or 3D model paths and links to a separate 3D article. — [SnapMagic: How to import into KiCad v6 and later](https://support.snapmagic.com/en/articles/5995733-how-to-import-into-kicad-v6-and-later)
- 3D models: "the 3D models are not integrated with the footprint" and must be linked manually. Models are downloaded separately when available. — [SnapMagic: how to add libraries on KiCad using the SnapEDA desktop app](https://support.snapmagic.com/en/articles/5612390-how-to-add-libraries-on-kicad-using-snapeda-desktop-app)
- A third-party automation playbook (unofficial, reads like an internal wiki) states: zip is `<MPN>.zip` containing `<MPN>.kicad_sym` and `<MPN>.kicad_mod` at top level (folder structure not described); the STEP is a separate download named `<MPN>--3DModel-STEP-<id>.STEP` and is "always raw STEP regardless of preferred-format"; the KiCad format variant is an account preference (`kicad_modv6` = "KiCad V6 & Later", also v4 and v3 variants); repeat downloads become `<MPN> (1).zip`; parts with multiple symbol sections show a "Heads Up" modal. — [adom chip-fetcher SnapMagic playbook](https://wiki.adom.inc/api/pages/adom/chip-fetcher/files/playbooks/snapmagic.md)
- SnapEDA warns that the zip name stays exactly the part number with no "(1)" suffix and that "this can cause import issues in KiCad." — snippet from search result, [SnapMagic support](https://support.snapmagic.com/en/articles/5612390-how-to-add-libraries-on-kicad-using-snapeda-desktop-app) (the claim came through a search summary, not a verbatim read; treat as medium confidence)
- A University of Texas guide warns that after downloading, "usually the directory doesn't work": the symbol's footprint link needs fixing. — [UT Austin wiki](https://cloud.wikis.utexas.edu/wiki/x/Eo_vAQ) (from search summary)
- An older KiCad forum answer says the fix for an unlinked footprint is to change the symbol's footprint field to include the library name, and that other SnapEDA/UL parts worked without that change. — [KiCad forum: forgetting-3d-custom-parts / search result summary](https://forum.kicad.info/t/forgetting-3d-custom-parts/55270)

**SamacSys / Component Search Engine / Mouser Library Loader (documentation only, no real sample available)**
- The Library Loader historically produced legacy `.lib`, `.mod` and `.dcm` files (KiCad 5 era); SamacSys instructions use `SamacSys_Parts.lib`/`.mod` for KiCad 5+, and a `SamacSys_Parts.kicad_sym` plus `SamacSys_Parts.pretty` for newer KiCad. Manual downloads from the website are a zip. — [KiCad forum: Footprint of SamacSys component shown as invalid](https://forum.kicad.info/t/footprint-of-samacsys-component-shown-as-invalid-in-schematic-editor/60895); [SamacSys KiCad page](https://www.samacsys.com/?p=321860)
- Known defect: footprint reported "invalid" in the schematic editor because the symbol's Footprint property lacked the `SamacSys_Parts:` prefix; re-assigning it via the chooser added the prefix. Users disagree on the cause; the poster reported it to SamacSys. — [KiCad forum thread](https://forum.kicad.info/t/footprint-of-samacsys-component-shown-as-invalid-in-schematic-editor/60895)
- KiCad can non-destructively convert old `.lib`/`.mod` libraries to `.kicad_sym`/`.kicad_mod` when registering them; a poster says older-format vs newer-KiCad version "doesn't matter at least between KiCad versions 6...9." — same thread
- SamacSys states its CAD models include 3D models; a third-party MCP tool describes the output as raw `.kicad_sym`/`.kicad_mod` contents. — [Supplyframe SamacSys](https://supplyframe.com/samacsys); [glama cse_get_kicad](https://glama.ai/mcp/servers/Averyy/pcbparts-mcp/tools/cse_get_kicad)

### Inferences
- The importer cannot rely on file names for anything on UL: symbol file is a timestamp, STEP stem and footprint stem differ, STEP sits outside the `KiCADv6/` folder. Pairing must be by structure (the single `.kicad_mod`, the single `.stp/.step`, the symbol's own name).
- Because UL's symbol Footprint value has no nickname, the importer must always rewrite it to `<Lib>:<FP>` (the project's core value). For SnapEDA/SamacSys the same rewrite should be applied unconditionally rather than only when a nickname is missing, since forum evidence shows both missing and wrong values.
- UL footprints in the sample have no `(model)` token, so "fix the model path" for UL means adding a `(model "${CUSTOM_3DMODEL_DIR}/<file>.step" (offset (xyz 0 0 0)) (scale (xyz 1 1 1)) (rotate (xyz 0 0 0)))` block, not rewriting one. For SnapEDA/SamacSys, whether a `(model)` exists is unknown.
- UL all-`unspecified` pin types is a default one-sample observation, not proof UL always does this. An importer cannot infer correct pin types and should at most report them in the preview (e.g. "8 pins, all unspecified").
- Old-format input (`(id N)`, bare `hide`, `fp_text`, `(width)`) means an importer that edits text with regex must handle both legacy and KiCad-10-style syntax if it edits inside the files. Safer is to round-trip through KiCad (see Q2 gaps), or restrict regex edits to the few well-defined tokens.

### Gaps
- No real SnapEDA, SamacSys/CSE or loose-file sample exists in `downloaded_examples/` yet, so their symbol version, footprint version, `(model)` content, naming and pin types are unverified. The project's own constraints already note this.
- Whether SnapEDA zips ever contain a `.pretty` folder or STEP inside the KiCad zip (sources conflict: official help says only `.kicad_sym` + `.kicad_mod`; one SnapEDA Q&A title says "the footprint .pretty file is not in the zip", which returned HTTP 410 so could not be read).
- I found no source describing SamacSys' current zip layout (folder names, `.step`/`.stp` presence); the "LIB_" prefix I was asked about could not be confirmed.
- Whether UL's "KiCad v7/v8/v9" export options differ from "KiCADv6" in the zip name/format: not checked.

## Q2. Which KiCad 10 file format versions apply to .kicad_sym and .kicad_mod, what is new vs KiCad 8/9, are old files accepted, and what breaks regex editing?

### Takeaway
On the KiCad 10.0 branch the symbol library format version is 20251024 and the footprint/board format version is 20260206; KiCad 10-written files are tab-indented multi-line S-expressions with new `(show_name no)` / `(do_not_autoplace no)` entries inside every symbol property and `(hide yes)` booleans. Older files (the 20211014 UL sample, KiCad 6-9) are expected to load because KiCad keeps parsers for older versions, but a file saved by 10 may not open in 9; this is relevant because plain regexes written against one style will miss the other.

### Cited Findings
- KiCad 10.0 branch source: `SEXPR_SYMBOL_LIB_FILE_VERSION 20251024  // Updated properties formatting (do_not_autoplace, show_name)` and `SEXPR_SCHEMATIC_FILE_VERSION 20260306`. — [sch_file_versions.h, 10.0 branch](https://gitlab.com/kicad/code/kicad/-/raw/10.0/eeschema/sch_file_versions.h)
- KiCad 10.0 branch source: `SEXPR_BOARD_FILE_VERSION 20260206  // Fix barcode and variant attribute serialization`; this constant is also what a `.kicad_mod` footprint file carries (the official footprint `R_0603_1608Metric.kicad_mod` on master has `(version 20260206)`). — [pcb_io_kicad_sexpr.h, 10.0 branch](https://gitlab.com/kicad/code/kicad/-/raw/10.0/pcbnew/pcb_io/kicad_sexpr/pcb_io_kicad_sexpr.h); [official footprint R_0603_1608Metric](https://gitlab.com/kicad/libraries/kicad-footprints/-/raw/master/Resistor_SMD.pretty/R_0603_1608Metric.kicad_mod)
- Symbol format history relevant to KiCad 8 -> 10 (symbol lib versions): 20231120 `generator_version; V8 cleanups` (KiCad 8); 20240529 Embedded Files; 20240819 embedded-files hash switched to Murmur3; 20241209 private flags for fields; 20250318 `~` no longer means empty text; 20250324 Jumper pin groups; 20250829 Rounded rectangles; 20250901 Stacked pin notation; 20250925 Bus alias in project file; 20251024 properties formatting (do_not_autoplace, show_name). — [sch_file_versions.h, 10.0 branch](https://gitlab.com/kicad/code/kicad/-/raw/10.0/eeschema/sch_file_versions.h)
- Footprint/board format history relevant to KiCad 9 -> 10 (board versions, applicable to `.kicad_mod`): 20240706 Embedded Files; 20240819 hash algorithm to Murmur3; 20240929 complex padstacks; 20250818 custom layer counts in footprints; 20250829 rounded rectangles; 20250909 footprint unit metadata (units/pins); 20250914 barcode objects; 20251028 stop writing netcodes; 20251101 backdrill/tertiary drill; 20260101 PCB variants with per-footprint overrides; 20260206 barcode and variant attribute serialization fix. — [pcb_io_kicad_sexpr.h, 10.0 branch](https://gitlab.com/kicad/code/kicad/-/raw/10.0/pcbnew/pcb_io/kicad_sexpr/pcb_io_kicad_sexpr.h)
- Master (KiCad 11 development) is already at symbol-lib version 20261015 ("Custom user properties for SCH_SHAPEs") and has 2026 entries such as pin-to-pad maps (20260629), line ending shapes (20260710), bold as stroke-width multiplier (20260826). These are not in 10.0. — [sch_file_versions.h doxygen (master snapshot)](https://docs.kicad.org/doxygen/sch__file_versions_8h_source.html)
- Real KiCad 10 symbol file (official library `Device.kicad_symdir/R.kicad_sym`): header is multi-line, tab-indented: `(kicad_symbol_lib (version 20251024) (generator "kicad_symbol_editor") (generator_version "10.0")`, quoted generator, `(exclude_from_sim no)`, `(in_bom yes)`, `(on_board yes)`, `(in_pos_files yes)`, `(duplicate_pin_numbers_are_jumpers no)`, and every property has `(at ...)`, `(show_name no)`, `(do_not_autoplace no)`, optionally `(hide yes)`, then `(effects (font (size ..)))` each on its own line. Property `Footprint` is `""` for generic parts. — [Device.kicad_symdir/R.kicad_sym on master](https://gitlab.com/kicad/libraries/kicad-symbols/-/raw/master/Device.kicad_symdir/R.kicad_sym)
- Real KiCad 10 footprint: tab-indented multi-line; `(footprint "NAME" (version 20260206) (generator "kicad-footprint-generator") (layer "F.Cu") (descr ...) (tags ...)`; footprint text is stored as `(property "Reference" "REF**" (at ..) (layer ..) (effects ...))`, `Value`, and further custom properties with `(hide yes)`; the 3D model block is `(model "${KICAD10_3DMODEL_DIR}/Resistor_SMD.3dshapes/R_0603_1608Metric.step" (offset (xyz 0 0 0)) (scale (xyz 1 1 1)) (rotate (xyz 0 0 0)))`. — [R_0603_1608Metric.kicad_mod on master](https://gitlab.com/kicad/libraries/kicad-footprints/-/raw/master/Resistor_SMD.pretty/R_0603_1608Metric.kicad_mod)
- Dev docs: the symbol and footprint library format documents "all versions of KiCad from 6.0"; before version 6 strings were only quoted when necessary; `version` is YYYYMMDD and `generator` identifies the writer; third-party scripts should not use `kicad_symbol_editor` as generator id; the footprint token was `module` before version 6. — [dev-docs symbol lib](https://dev-docs.kicad.org/en/file-formats/sexpr-symbol-lib/index.html); [dev-docs footprint](https://dev-docs.kicad.org/en/file-formats/sexpr-footprint/index.html); [dev-docs sexpr intro](https://dev-docs.kicad.org/en/file-formats/sexpr-intro/index.html)
- Dev docs (intro page, partly outdated: newest version it references is 7) say `model` takes `scale` and `rotate`; the documented footprint property syntax is `[(property "KEY" "VALUE") ...]`; mandatory symbol properties are Reference, Value, Footprint, Datasheet (plus Description in newer versions). — [dev-docs sexpr intro](https://dev-docs.kicad.org/en/file-formats/sexpr-intro/index.html)
- Version-compat observations from users: a symbol saved by KiCad 10 "could no longer be opened in V9" (back up libraries first); forum poster states library handling for older-format files has not changed between 6 and 9 (they load fine). — [KiCad forum: V10 Windows no symbol libraries found](https://forum.kicad.info/t/v10-windows-no-symbol-libraries-found/67890); [forum thread on SamacSys](https://forum.kicad.info/t/footprint-of-samacsys-component-shown-as-invalid-in-schematic-editor/60895)
- A KiCad 10 symbol-library layout change: KiCad 10 supports packed (`.kicad_sym`, multiple symbols per file) and unpacked (`.kicad_symdir` directory containing one `.kicad_sym` per symbol, parent-derived symbols also separate). Official libraries are shipped packed (their repo stores them unpacked). A forum developer states "There is no new library structure. There are still many symbols in each .kicad_sym file" for end users. — [KiCad forum: v10 new library handling kicad_symdir unpacked](https://forum.kicad.info/t/v10-new-library-handling-kicad-symdir-unpacked/68546); [forum: V10 Windows no symbol libraries found](https://forum.kicad.info/t/v10-windows-no-symbol-libraries-found/67890)
- `kicad-cli sym upgrade --force foo.kicad_sym -o unpacked/foo.kicad_symdir/` is cited as the way to unpack; there is also `kicad-cli sym upgrade` generally (rewrites a library in the current format). Unpacked-to-packed conversion was reported failing in a KiCad issue. — [forum thread](https://forum.kicad.info/t/v10-new-library-handling-kicad-symdir-unpacked/68546); [KiCad issue 22912](https://gitlab.com/kicad/code/kicad/-/issues/22912)
- Footprints in KiCad 10 can now hold graphics, keepouts and other objects on inner layers; the Symbol Editor Pin Table supports CSV import/export; local power symbols and multiple alternate body styles were added. — [KiCad 10.0.0 release](https://www.kicad.org/blog/2026/03/Version-10.0.0-Released/)

### Inferences
- Regex hazards for a KiCad 10 round-trip: (1) property blocks are now multi-line with tabs (the local UL sample is single-line-ish with spaces and `(id N)`), so any regex like `\(property "Footprint" "[^"]*"` works for the value in both, but anything anchored on `(at ...)` or `hide` position/format will not; (2) `hide` is bare flag in 20211014, `(hide yes)` in 20241004+; (3) the symbol's `(generator "kicad_symbol_editor")` quoting differs; (4) `(version N)` must be matched as a number, not assumed single-line; (5) a symbol library holds many symbols, and derived symbols use `(extends "Parent")`, so rewriting "the" Footprint property needs scoping to the right top-level symbol and its sub-symbols (`NAME_1_1`) must not be touched; (6) `${...}` appears in `fp_text user "${REFERENCE}"` as well as in model paths, so path regexes must be scoped to the `(model "...")` token.
- Adding a symbol to a packed library by text insertion is plausible (append before the final `)`), but the new symbol should be written in a form KiCad can parse. Old-format input pasted into a 10-version library is expected to be accepted, since the loader handles older constructs, but I found no explicit statement of this for mixed-version libraries, so treat it as untested.
- Simplest safe design: insert the vendor symbol text verbatim and only rewrite the `Footprint` property value and a small set of other fields; optionally call `kicad-cli sym upgrade` (outputs a file in the current format) in a temp dir to normalise before merging. I found no evidence of a `kicad-cli fp upgrade`-style command being a problem; `kicad-cli fp upgrade` exists in KiCad 8+ (from my background knowledge, not verified in this research).

### Gaps
- I could not find the official KiCad 10 documentation statement that "KiCad 6-9 files are accepted and upgraded on load"; the claim rests on dev-docs ("all versions from 6.0"), the version-history mechanism in the source, and forum posts. The 20211014 UL sample was not loaded in KiCad 10 by me.
- Whether KiCad 10 writes any `generator_version` into `.kicad_mod` files, or whether it keeps `(generator "pcbnew")`: the official library footprint uses `"kicad-footprint-generator"`; a KiCad-saved footprint was not inspected.
- The dev-docs pages for symbol/footprint do not list the 8/9/10 token additions (they stop at ~v7). The authoritative list is the source header comments cited above; the exact syntax of tokens added in 9/10 (stacked pin notation, pin-to-pad maps are master-only, jumper pin groups, `show_name`, etc.) was not collected beyond the sample file.
- Behavioral specifics of how 10 handles the legacy `(id N)` token (silently ignored vs warning) not verified.

## Q3. How does KiCad 10 handle path variables for 3D models, kicad_common.json, library tables, and third-party libraries?

### Takeaway
KiCad 10's built-in 3D variable is `KICAD10_3DMODEL_DIR`; older versioned variables (`KICAD9_...`) auto-resolve to the current version's value unless explicitly defined. User variables (such as `CUSTOM_3DMODEL_DIR`) live in the per-version `kicad_common.json` under `environment.vars`, in `%APPDATA%\kicad\10.0` on Windows, and system environment variables outrank the Configure Paths dialog. KiCad 10 also introduced chained/nested library tables ("Table" type) and unpacked symbol libraries, so the global `sym-lib-table` may now contain a nested-table entry rather than a flat list.

### Cited Findings
- `KICAD10_3DMODEL_DIR` = "Base path of KiCad's standard 3D footprint model library files." `KICAD_USER_TEMPLATE_DIR` = personal project templates. `KIPRJMOD` is set automatically and cannot be redefined. — [KiCad 10 docs: KiCad main window / paths](https://docs.kicad.org/10.0/en/kicad/kicad.html)
- "KiCad will automatically resolve versioned path variables from older versions of KiCad" to the current version's value if the old variable is not defined, e.g. `${KICAD9_FOOTPRINT_DIR}` resolves to `${KICAD10_FOOTPRINT_DIR}`. — [KiCad 10 docs](https://docs.kicad.org/10.0/en/kicad/kicad.html); [forum: Default KiCad 3DModels Library path](https://forum.kicad.info/t/default-kicad-3dmodels-library-path/69934)
- Unversioned `KICAD_*` names are NOT resolved the same way (a request to add that is GitLab work item 24727). — [forum: Default KiCad 3DModels Library path](https://forum.kicad.info/t/default-kicad-3dmodels-library-path/69934)
- Paths set as system environment variables outside KiCad take precedence over Configure Paths; "You cannot override a system environment variable that has been set outside of KiCad by using the Configure Paths dialog." `KICAD_CONFIG_HOME` changes the base config path; each minor version gets its own subfolder. For KiCad 10 on Windows that is `%APPDATA%\kicad\10.0`. — [KiCad 10 docs](https://docs.kicad.org/10.0/en/kicad/kicad.html)
- Local KiCad 9.0 observation (not 10): `%APPDATA%\kicad\9.0\kicad_common.json` has `meta: {filename: "kicad_common.json", version: 3}` and `environment.vars` holding this repo's user variables: `CUSTOM_3DMODEL_DIR`, `KICAD_LIB_GITHUB`, `WE_3DMODEL_DIR`. A `sym-lib-table` in the same folder starts with `(sym_lib_table (version 7) (lib (name ...)(type "KiCad")(uri "${KICAD9_SYMBOL_DIR}/....kicad_sym")(options "")(descr ...)))` and the folder contains `fp-lib-table`, `design-block-lib-table`. Config dirs present: `7.0`, `8.0`, `9.0`; no `10.0`. — local machine, `C:\Users\sylvain\AppData\Roaming\kicad\9.0\`
- The KiCad 10 docs page does not mention `kicad_common.json` by name; a forum post says user-defined env variables live in `kicad_common.json` and that defaults are not written to the file. — [KiCad 10 docs](https://docs.kicad.org/10.0/en/kicad/kicad.html); [forum search results](https://forum.kicad.info/t/versioning-configure-paths-environment-variables/39000)
- KiCad 10 shipped 3D models as STEP only (VRML removed from the official libraries; VRML generation deprecated, being stripped from the packages-3D repo). Upgraded PCBs referencing `KICAD9_3DMODEL_DIR/...wrl` may show missing models; fixes mentioned: KiCad 10.0.3 suggests replacements when the PCB editor opens, or define the old versioned variable, or text-replace `KICAD8_3DMODEL_DIR`->`KICAD10_3DMODEL_DIR` and `.wrl`->`.step`. — [KiCad 10.0.0 release](https://www.kicad.org/blog/2026/03/Version-10.0.0-Released/); [KiCad 10 migration epic](https://gitlab.com/groups/kicad/libraries/-/epics/14); [forum: KiCad v10 can't use its own footprints](https://forum.kicad.info/t/kicad-v10-cant-use-it-own-footprints-want-v9-instead/67985); [forum: KiCad 9 to KiCad10 3D file](https://forum.kicad.info/t/kicad-9-to-kicad10-3d-file/69628)
- A caveat from a forum user: when a custom path is set in a versioned variable, KiCad "ignores the system model path and only looks at my local path," so a local override can hide the system library. — [forum: Default KiCad 3DModels Library path](https://forum.kicad.info/t/default-kicad-3dmodels-library-path/69934) (from search summary)
- Library tables: global `sym-lib-table` / `fp-lib-table` live in the user config directory and apply to all projects; an optional project-level table lives in the project directory. — [KiCad 10 docs](https://docs.kicad.org/10.0/en/kicad/kicad.html)
- KiCad 10 new: library tables can be chained (nested "Table" library type; GitLab #3935 implemented), "used by default when installed in a standard way", so the default global `sym-lib-table` points to another table (template under `C:\Program Files\KiCad\10.0\share\kicad\template\sym-lib-table`), and the global list can look empty in older tooling. Disabling libraries inside nested tables is problematic (GitLab #23089). — [forum: Remember to test before v10: library tables](https://forum.kicad.info/t/remember-to-test-before-v10-library-tables/66994); [forum: V10 Windows no symbol libraries found](https://forum.kicad.info/t/v10-windows-no-symbol-libraries-found/67890); [forum: Kicad 10 missing libraries?](https://forum.kicad.info/t/kicad-10-missing-libraries/69944)
- "Reset Libraries" in Manage Symbol Libraries rebuilds the global table from the template and "cannot be undone"; users also report some 10.0.0 installs ended up with only a single Table entry. The 10.0.1 release was expected to import library settings from v9 more smoothly. Library renames in KiCad 10 (e.g. MCU_WCH...) leave stale entries in a table carried over from v9. — [forum: V10 Windows no symbol libraries found](https://forum.kicad.info/t/v10-windows-no-symbol-libraries-found/67890); [forum: Kicad 10 missing libraries?](https://forum.kicad.info/t/kicad-10-missing-libraries/69944)
- KiCad 10 checks for folders named `*.kicad_symdir` and adds all files under them; user-created unpacked libraries are added to the table by creating the directory first (the New Library command does not create it). — [forum: V10 Windows no symbol libraries found](https://forum.kicad.info/t/v10-windows-no-symbol-libraries-found/67890); [forum: v10 new library handling](https://forum.kicad.info/t/v10-new-library-handling-kicad-symdir-unpacked/68546)
- A forum user recommends a custom path variable (e.g. `KICAD_CUSTOM`) and defining symbol/footprint paths relative to it, and avoiding adding the same path both in path settings and as a directly linked library. — [forum: custom libraries are missing](https://forum.kicad.info/t/custom-libraries-are-missing/68925)

### Inferences
- The project's `${KICAD_LIB_GITHUB}` / `${CUSTOM_3DMODEL_DIR}` user variables are not versioned, so they should not be affected by the 9->10 variable rename; the versioned-variable fallback only matters for `KICAD*_3DMODEL_DIR` references that vendor files might contain (rare for vendor downloads).
- `kicad_common.json` for 10 is expected at `%APPDATA%\kicad\10.0\kicad_common.json` with the same `environment.vars` structure as 9 (meta version 3 observed in 9; 10's meta version not checked). The importer's existing `sync_kicad_path_vars` should detect the newest `N.0` folder (not hardcode 9) and may need to write into more than one version folder.
- If the project's table generator writes a flat `sym-lib-table`/`fp-lib-table` with `(version 7)`, it should still be readable by KiCad 10 since flat tables remain valid; the risk is the importer merging into a KiCad 10 *global* table that is now a nested/chained table, where a naive regex merge could miss entries. This repo writes tables in the repo root (not the global table), so impact is limited, but any "install into global table" step should be tested against a real 10.0 table.
- KiCad 10's new unpacked-library mechanism does not change the repo's `.kicad_sym` + `.pretty` pairing convention; packed `.kicad_sym` remains the normal and best-performing form on Windows (developer quote: Windows has a large penalty accessing thousands of small files).

## Q4. Does KiCad 10 support embedding 3D models in footprints and fonts/data in libraries, and how could that change importer design?

### Takeaway
Embedded files (3D models, fonts, datasheets, worksheets, other) have been supported in the file formats since KiCad 9 (format versions 20240529 symbols, 20240706 boards/footprints), and are present in 10. The official KiCad library convention forbids embedding in library symbols/footprints, and git/diff friendliness argues against it for this repo; the importer should keep external STEP files and `${CUSTOM_3DMODEL_DIR}` paths, but must not choke on files that already contain `embedded_files`.

### Cited Findings
- Embedding was added in KiCad 9; a user reported that you can embed STEP files and reference them with a `kicad-embed://` URL; an "embed model" checkbox exists in the 3D model assignment dialog (9.0.3+). Batch-embedding all footprints' models is not implemented. — [forum: Embedded 3D models in footprints](https://forum.kicad.info/t/embedded-3d-models-in-footprints/62503); [forum: Embed all footprints/models at once?](https://forum.kicad.info/t/embed-all-footprints-models-at-once/60905)
- Format history: symbol lib 20240529 "Embedded Files", 20240819 hash algorithm Murmur3; board/footprint 20240706 "Embedded Files", 20240819 Murmur3. — [sch_file_versions.h, 10.0](https://gitlab.com/kicad/code/kicad/-/raw/10.0/eeschema/sch_file_versions.h); [pcb_io_kicad_sexpr.h, 10.0](https://gitlab.com/kicad/code/kicad/-/raw/10.0/pcbnew/pcb_io/kicad_sexpr/pcb_io_kicad_sexpr.h)
- Serialisation (source `common/embedded_files.cpp`): one `(embedded_files (file (name ...) (type ...) (data ...) (checksum ...)) ...)` list; types are `datasheet`, `font`, `model`, `worksheet`, `other`; data is Zstandard-compressed (level 15), Base64-encoded, wrapped in 76-character lines with `|` bar delimiters at start and end; checksum is MMH3 of the uncompressed bytes (64-char values treated as SHA-256). `EMBEDDED_FILE::GetLink()` builds a `<prefix>://<name>` link (prefix constant not shown in the excerpt). — [embedded_files.cpp, 10.0 branch](https://gitlab.com/kicad/code/kicad/-/raw/10.0/common/embedded_files.cpp)
- KiCad Library Convention G1.10 reportedly says library symbols and footprints must not contain embedded files, with licensing and file-size reasons. — search-result summary of [KLC G1.10](https://klc.kicad.org/general/g1/g1.10) (page itself returned HTTP 403, so not read directly; medium confidence)
- Fonts: the `face` token (TrueType family) and `render_cache` for missing fonts exist since format version 7; embedded fonts are a type of embedded file. — [dev-docs sexpr intro](https://dev-docs.kicad.org/en/file-formats/sexpr-intro/index.html); [embedded_files.cpp](https://gitlab.com/kicad/code/kicad/-/raw/10.0/common/embedded_files.cpp)
- User criticisms: embedding bloats files (one example: board section ~12 KB vs STEP ~2.5 MB / 60,000 lines), and is unattractive for version-controlled or database libraries; a known bug (GitLab 20495) reuses an already-embedded model without checking whether a replaced file is the same. — [forum: Cache/Embed 3D model in footprint](https://forum.kicad.info/t/cache-embed-3d-model-in-footprint/19371); [GitLab issue 20495](https://gitlab.com/kicad/code/kicad/-/issues/20495)
- KiCad 10 PCBs routinely embed models: users report full standard footprint and 3D model data embedded in `.kicad_pcb` files and that embedded model extensions moved from WRL to STEP on upgrade. — [forum: KiCad 9 to KiCad10 3D file](https://forum.kicad.info/t/kicad-9-to-kicad10-3d-file/69628)

### Inferences
- Keep the importer design as-is (separate `.step` file under `Custom/3DModels/`, `(model "${CUSTOM_3DMODEL_DIR}/<file>.step" ...)` in the footprint). Embedding would make `.kicad_mod` multi-MB base64 blobs (bad for diffs, `git` repo size, and regex editing) and conflicts with KiCad's own library convention.
- The importer should detect `(embedded_files` in an incoming vendor symbol or footprint (not seen in any vendor sample so far) and either warn or extract the `model` entry (decode `|`-delimited base64 -> zstd decompress; needs the `zstandard` module or `kicad-cli`), rather than blindly copying it. This is an edge case; low priority.
- Regex edits that use `.*` across lines or assume no `|` characters could be confused by embedded data blocks; guard with a check for `embedded_files` before any whole-file regex.

### Gaps
- I could not verify the literal `kicad-embed` URI prefix constant from source, or the user-facing KiCad 10 docs text for embedding in footprint properties.
- Whether KiCad 10 can embed fonts into *symbol/footprint library files specifically* (vs only boards/schematics) was not verified; the file-format versions suggest the mechanism exists for symbols and footprints (both got "Embedded Files" versions).
- KLC G1.10 text was not read directly (403).

## Q5. Git-friendliness: KiCad 10 changes affecting diffs and library versioning

### Takeaway
KiCad 10 gives libraries more git-friendly options (unpacked per-symbol `.kicad_symdir`, shareable chained tables) but also changes formatting rules that cause large diffs when a library written by an older version is re-saved. For this repo (one packed `.kicad_sym` per category) the main practical risks are format-version churn when KiCad re-saves a file and hand-edited vs KiCad-saved style mix.

### Cited Findings
- Unpacked symbol libraries exist so "editing neighboring symbols doesn't cause VCS conflicts" and ordinary file tools work on single symbols; the official symbols repo is stored unpacked and packed at build time (`KICAD_PACK_SYM_LIBRARIES`). Caveats: filenames follow OS rules (e.g. `%` in symbol names fails on Windows), and Windows is slow with thousands of small files, so packed is recommended for use. — [forum: v10 new library handling](https://forum.kicad.info/t/v10-new-library-handling-kicad-symdir-unpacked/68546); [allspice mirror of kicad-symbols](https://hub.allspice.io/AllSpiceMirrors/kicad-symbols)
- Chained library tables let teams point to a git-hosted table so that a teammate's library updates on KiCad restart without each user editing their global table. — [forum: custom libraries are missing](https://forum.kicad.info/t/custom-libraries-are-missing/68925); [forum: Remember to test before v10: library tables](https://forum.kicad.info/t/remember-to-test-before-v10-library-tables/66994)
- KiCad 10 writes a changed property format (`show_name`, `do_not_autoplace` on every symbol property; `(hide yes)`), and stops writing netcodes in boards (20251028); `kicad-cli sym upgrade` rewrites a library into current format. — [sch_file_versions.h, 10.0](https://gitlab.com/kicad/code/kicad/-/raw/10.0/eeschema/sch_file_versions.h); [pcb_io_kicad_sexpr.h, 10.0](https://gitlab.com/kicad/code/kicad/-/raw/10.0/pcbnew/pcb_io/kicad_sexpr/pcb_io_kicad_sexpr.h); [forum thread](https://forum.kicad.info/t/v10-new-library-handling-kicad-symdir-unpacked/68546)
- Files saved in KiCad 10 may not reopen in KiCad 9 (user report), so a library mixing 9-saved and 10-saved content is a one-way upgrade. — [forum: V10 Windows no symbol libraries found](https://forum.kicad.info/t/v10-windows-no-symbol-libraries-found/67890)
- Embedded files are Base64-encoded compressed binary, which diffs poorly (see Q4).

### Inferences
- Appending a vendor symbol into an existing `.kicad_sym` in the file's existing style yields small diffs; round-tripping the whole library through KiCad 10 will rewrite every symbol's properties once (a one-time large diff), then stay stable. The importer should avoid calling any "upgrade" step implicitly and should show the preview diff (already required).
- Consider recording which KiCad version the `Custom/` submodule libs were last saved with, because a 10-saved library is not safe for a 9-only collaborator. For a personal tool this is minor.
- `.kicad_symdir` would be a git-friendlier layout for `Custom/` but conflicts with the repo's pairing convention (`Foo.kicad_sym` + `Foo.pretty`), the scanner (`find_symbol_libs` looks for `.kicad_sym` files), and Windows performance; not recommended without a clear need.

### Gaps
- No KiCad 10 document or release note was found that specifically addresses git diffs or library versioning beyond the points above.
- Not verified: whether KiCad 10 emits deterministic ordering and stable uuids for symbols/footprints on save (relevant for diff noise).
