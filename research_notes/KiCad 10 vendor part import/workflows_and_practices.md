# Community practice and best-practice workflows for personal KiCad part libraries in git (KiCad 9/10, as of Oct 2026)

Method note: research done 2026-10-18 with web search and page fetches. Forum posts and third-party summaries are labelled as opinion/anecdote where relevant. Several official pages (klc.kicad.org, dev-docs.kicad.org detail pages) returned HTTP 403 to the fetch tool, so KLC claims rely on search-result snippets and are flagged.

## 1. Common patterns for custom libraries in git (submodules vs monorepo vs PCM) and relation to KLC and a `<Type>_<SubCategory>_<Manufacturer>` scheme

### Takeaway
The dominant community advice is one central personal-library repo consumed by projects (often as a submodule) and located through path variables. This matches the repo's current design. KLC organises libraries by function, with manufacturer as a late naming element, which is broadly compatible with `<Type>_<SubCategory>_<Manufacturer>`. KiCad libraries are a flat list, so hierarchy must live in names. Submodules are contested in the forum, and PCM is an alternative distribution route that bypasses KLC.

### Cited Findings
- (Opinion, forum consensus summarised by search) Most sources favour a single personal library repo included in projects as a git submodule with relative paths or path variables. Dissenters warn that submodules or committed library copies mean you start changing local copies, and one poster says submodules are "natural for a code library... not so for a CAD system". — [Library structure best practices](https://forum.kicad.info/t/library-structure-best-practices/22768), [Need advice for managing own library repo / project repo](https://forum.kicad.info/t/need-advice-for-managing-own-library-repo-project-repo/1760), [Freetronics library management wiki](https://github.com/freetronics/freetronics_kicad_library/wiki/Library-Management), [LBL Atlas wiki KiCad git](https://atlaswiki.lbl.gov/guides/kicad/git). These threads are largely KiCad 5/6 era.
- (Fact, from the Freetronics guide) A submodule pins a project to a specific library revision, so library edits do not silently change old projects, but fresh clones need `git submodule init` or library access fails. — [Freetronics wiki](https://github.com/freetronics/freetronics_kicad_library/wiki/Library-Management)
- (Fact) KLC states libraries are organised by component functionality rather than manufacturer; the naming pattern is function, sub-function, qualifier, manufacturer, series, then extra descriptors. Connector libraries are the main exception where manufacturer-oriented libraries exist. Source is a search-result snippet of the KLC page (page itself returned 403) plus a forum reply. — [KLC G1.3](https://klc.kicad.org/general/g1/g1.3), [Grouped libraries thread](https://forum.kicad.info/t/grouped-libraries/21163)
- (Fact) KiCad libraries are a flat, one-level list with no sub-levels in the library tree. — [Grouped libraries thread](https://forum.kicad.info/t/grouped-libraries/21163)
- (Opinion) Personal-library advice diverges: some prefer one library per MPN with search doing the work; no thread settled per-category vs per-manufacturer for personal libraries. Vendor libraries (Digi-Key partner library) group by supplier. — [Grouped libraries thread](https://forum.kicad.info/t/grouped-libraries/21163), [digikey-partner-kicad-library](https://github.com/digi-key/digikey-partner-kicad-library)
- (Fact) Path variables only make a setup portable; each library must still be registered in the sym-lib-table / fp-lib-table. Project-local libraries should use `${KIPRJMOD}`. — [Library management in KiCad version 5](https://forum.kicad.info/t/library-management-in-kicad-version-5/14636), [KiCad 6 paths and libraries guide](https://techexplorations.com/guides/kicad/3e/kicad-paths-and-libraries)
- (Anecdote, KiCad 10) Users report that after upgrading, custom libraries intermittently failed to appear in 10.0.x, and that library path variables were imported wrongly on first run of KiCad 10; one suggested fix is a single custom path variable with libraries relative to it. This is relevant because the repo depends on `KICAD_LIB_GITHUB` and `CUSTOM_3DMODEL_DIR`. — [Custom libraries are missing](https://forum.kicad.info/t/custom-libraries-are-missing/68925), [KiCad 10 libraries path wrong imported](https://forum.kicad.info/t/kicad-10-libraries-path-wrong-imported-from-previous-version-on-first-run/67824)
- (Anecdote) A KiCad 10 forum post says library management changed significantly in V10: global/project library tables are now visible in the manager and both symbol and footprint libraries can be packed or unpacked. Single-user claim; not verified against official docs. — [Search snippet from forum thread results](https://forum.kicad.info/t/custom-libraries-are-missing/68925)
- (Fact) PCM can distribute a personal library: a custom repository is a hosted JSON file added in PCM "Manage"; private repos are possible; a library shipped this way does not need to follow KLC or await librarian approval, while inclusion in the official libraries requires both. The package zip must be built at the level containing the symbol/footprint folders. — [How to make a personal user library install under PCM](https://forum.kicad.info/t/how-to-make-a-personal-user-library-install-under-pcm/55589), [Adom PCM repository](https://wiki.adom.inc/adom/kicad-pcm)
- (Fact) Official KiCad 10 library statistics: 78% of footprints are generated from data; 3D libraries ship STEP only (VRML dropped). Relevant to using STEP for custom models. — [KiCad 10.0.0 release](https://www.kicad.org/blog/2026/03/Version-10.0.0-Released/)
- (Fact) The KiCad 10 library migration epic lists "update KLC" as still open (sub-issue 46), so KLC text may not yet reflect the symdir change. — [KiCad 10 migration epic](https://gitlab.com/groups/kicad/libraries/-/epics/14)

### Inferences
- The repo's `<Type>_<SubCategory>_<Manufacturer>` scheme is a reasonable adaptation of KLC's function-first naming (type and sub-category lead, manufacturer is third) and is not unusual; it does not need to be KLC-compliant because it is not destined for the official libraries.
- A submodule of a personal library repo is a defensible but not universally endorsed choice; its main benefit (pinning library revisions per project) matters most when a library part is later modified.
- PCM distribution would only matter if the library were shared with other people; for a personal tool it is unnecessary.

### Gaps
- No authoritative KiCad-project "best practice" document for personal libraries exists; the evidence is forum opinion, much of it from KiCad 5/6.
- klc.kicad.org returned 403, so the exact current wording of G1.x/S/F rules was not read directly.
- Nothing found on the monorepo-vs-submodule debate specifically from 2025-2026.

## 2. KiCad database libraries (.kicad_dbl) and KiCad 10 status: alternative to a vendor-package importer?

### Takeaway
No. A `.kicad_dbl` is a mapping layer over an external SQL database whose rows point at symbols that must already exist in ordinary `.kicad_sym` libraries, so it adds a metadata/selection layer rather than replacing import of vendor symbols and footprints. KiCad provides no GUI for creating or editing it, and forum opinion is that it is overkill for hobbyists. A KiCad 10 search regression with SQLite DBLs was reported by one user.

### Cited Findings
- (Fact, official docs) KiCad database libraries use ODBC only (tested with SQLite, MySQL, MariaDB, PostgreSQL). The `.kicad_dbl` is JSON with `source` and `libraries` entries mapping table columns to fields. — [KiCad 10 Eeschema docs, Database Libraries](https://docs.kicad.org/10.0/en/eeschema/eeschema.html)
- (Fact, official docs) KiCad has no GUI to edit the database or define the library; only text fields are supported; and any source library referenced by a table must also be in the symbol library table. Database rows reference symbols as `LibraryNickname:SymbolName` from other KiCad libraries. — [KiCad 10 Eeschema docs](https://docs.kicad.org/10.0/en/eeschema/eeschema.html)
- (Fact) The feature's stated primary audience is companies/organisations already using a database for part management. — [Post-v6 new features thread, as surfaced by search](https://forum.kicad.info/t/post-v6-new-features-and-development-news/32633/68)
- (Opinion) Some forum members regard DBLs as more bother than worth for hobbyists; others do use SQLite for personal parts. Maintenance chores include hand-updating the `.kicad_dbl` when tables are added and the Symbol Library Manager file chooser offering only `*.kicad_sym` (workaround: add a row, set type to Database, enter the path). — [Kicad_dbl using CSV without external binary database](https://forum.kicad.info/t/kicad-dbl-using-csv-without-external-binary-database/71506), [Can't point to .kicad_dbl from Symbol Library Manager](https://forum.kicad.info/t/cant-point-to-kicad-dbl-file-from-symbol-library-manager/64434), [My KiCAD component database](https://forum.kicad.info/t/my-kicad-component-database/56000)
- (Fact) Small teams use external parts managers (InvenTree, PartDB) via KiCad's HTTP library (merged for KiCad 8); these generate libraries or serve parts rather than importing vendor ZIPs. — [KiCad Database Library Management thread, 2024](https://forum.kicad.info/t/kicad-database-library-management/47356)
- (Anecdote, single user) On KiCad 10.0.3 a SQLite-backed DBL that worked in 9 no longer returns matches in symbol chooser search, and descriptions now come from the symbol rather than the database. Unconfirmed bug. — [Issue with component search from DB lib](https://forum.kicad.info/t/issue-with-component-search-from-db-lib/69588)
- (Fact) In the KiCad 10 thread on `.kicad_symdir`, developer jmk (Apr 22, 2026) suggested database libraries for company-specific parts and said there is no new library structure; `.kicad_sym` still holds many symbols. — [V10 new library handling (kicad_symdir)](https://forum.kicad.info/t/v10-new-library-handling-kicad-symdir-unpacked/68546)
- I found no KiCad 10 release-note item that changes DBL capabilities; the release post does not mention database libraries. — [KiCad 10.0.0 release](https://www.kicad.org/blog/2026/03/Version-10.0.0-Released/)

### Inferences
- DBL and a vendor importer are complementary: a DBL would still need correctly named, footprint-linked symbols to point at, which is exactly what the importer produces.
- For a personal library of a few dozen to a few hundred parts, a DBL adds an ODBC dependency and a second source of truth without removing the import chore.

### Gaps
- No official KiCad 10 DBL changelog was found. The "search regression" claim is one forum report and not a confirmed bug.
- Docs "Importing symbols" section was not read (page truncated in fetch).

## 3. How users handle SnapEDA / Ultra Librarian / SamacSys downloads; pain points a tool should address

### Takeaway
The workflow remains largely manual (unzip, add libraries via Manage Libraries, fix links). Documented pain points: missing library prefix in the symbol's Footprint field ("invalid footprint"), 3D models not linked or broken path, legacy-format files, vendor part quality, and no one-click path. Third-party importers exist (Import-LIB-KiCad-Plugin, SamacSys Library Loader, Impart-style tools), so a personal tool overlaps with them but differs in targeting a specific library convention and git workflow.

### Cited Findings
- (Fact) Ultra Librarian's own KiCad 6+ instructions are manual: add the symbol file through Manage Symbol Libraries and the `.pretty` folder through Manage Footprint Libraries. — [Ultra Librarian KiCad 6.0+ help](https://app.ultralibrarian.com/content/help/kicad-6_0.htm)
- (Anecdote, 2023) Importing a vendor `.kicad_sym` into an existing library does not bring the footprint; the symbol's Footprint field lacks the library prefix (e.g. `14010313102000` instead of `EK:14010313102000`), so KiCad flags it "invalid footprint". SamacSys Library Loader automates import but the prefix is still missing. — [Import Workflow thread, Oct 2023](https://forum.kicad.info/t/import-workflow/45503)
- (Anecdote, May 2025, KiCad 9.0.1) A SamacSys symbol showed "Invalid footprint specified" despite the footprint being linked; cause not confirmed; working fix was migrating the legacy library to current `.kicad_sym` and re-selecting the footprint in the chooser. Another poster said recent SamacSys downloads include `.kicad_sym`/`.kicad_mod` plus legacy `.lib/.mod/.dcm` files, and recommended using the new-format files. — [Footprint of SamacSys component shown as invalid](https://forum.kicad.info/t/footprint-of-samacsys-component-shown-as-invalid-in-schematic-editor/60895)
- (Fact, 2020-2022 era vendor docs; may be outdated) SnapMagic/SnapEDA downloads include 3D models but they are not integrated into the footprint; users attach the `.stp` manually in the footprint's 3D Settings; forum replies say the link must be saved into the library footprint and an environment variable should be used so moving the model does not break it. — [SnapMagic: why 3D model not integrated](https://support.snapmagic.com/en/articles/5742539-why-is-the-3d-model-not-integrated-with-the-library), [Forgetting 3D custom parts](https://forum.kicad.info/t/forgetting-3d-custom-parts/55270)
- (Fact) KiCad's symbol-library file chooser cannot look inside zip archives, so users must unzip first. — [Can not import .kicad_sym](https://forum.kicad.info/t/can-not-import-kicad-sym/48757/44)
- (Fact, vendor support answer) SnapEDA exporter once produced broken symbols due to a "/" in the symbol name (exporter fix promised). Windows filename rules matter for unpacked symdir names too (see Q4). — [SnapMagic question](https://www.snapeda.com/questions/question/problem), [symdir thread](https://forum.kicad.info/t/v10-new-library-handling-kicad-symdir-unpacked/68546)
- (Opinion, 2022 thread) SnapEDA footprints/symbols often have significant errors and symbols are often needlessly split into multiple units; crowdsourced ratings are not trusted; "trust but verify" against the datasheet is the advice. Automating import does not remove the need to check parts. — [SnapEDA UltraLibrarian Automated Import](https://forum.kicad.info/t/snapeda-ultralibrarian-automated-import/36000), [Import Workflow](https://forum.kicad.info/t/import-workflow/45503)
- (Fact) Existing tool: Import-LIB-KiCad-Plugin (Steffen-W) imports Octopart, SamacSys, Ultra Librarian, SnapEDA and EasyEDA packages, links footprint and 3D model to symbol, one library per source by default or a single library name option, `--overwrite-if-exists`, `--prefer-step`, 3D path variable defaulting to `${KICAD_3RD_PARTY}` (configurable with `--path-variable`), available via PCM. Release 2026.10.12 (Oct 12, 2026) requires KiCad 9.0+, no longer writes KiCad config files, and fixed "KiCad 9/10 symbol data being lost on import" and hidden-field loss. Earlier 2026.03.08 fixed multi-part symbol logic and SymbolPin v9 hide token. — [Import-LIB-KiCad-Plugin README](https://github.com/Steffen-W/Import-LIB-KiCad-Plugin), [releases API](https://api.github.com/repos/Steffen-W/Import-LIB-KiCad-Plugin/releases?per_page=5). README does not describe renaming or detailed duplicate detection.
- (Fact) Other importers: "Kicad open-source library loader/component importer" posted May 31, 2026 (ZIP processing, 3D handling, no replies); LCSC/EasyEDA importers; SamacSys Library Loader (reported as old/legacy-format by users). — [Library loader thread](https://forum.kicad.info/t/kicad-open-source-library-loader-component-importer/69521), [easyeda2kicad plugin](https://github.com/rasmushauschild/easyeda2kicad_plugin)
- (Fact) KiCad 10 `Update/Change footprints` gained a "match pad positions" option because libraries use different origins/orientations (relevant if re-linking footprints). — [Post-V10 news thread](https://forum.kicad.info/t/post-v10-new-features-and-development-news/66611)

### Inferences
- Pain points a personal tool can address, supported by the above: (1) writing `<Lib>:<FP>` into the symbol's Footprint property; (2) rewriting 3D `(model ...)` paths to a path variable and placing the STEP; (3) renaming to the library convention; (4) unzip and picking new-format files over legacy `.lib/.mod/.dcm`; (5) collision/duplicate handling when the symbol or footprint name already exists; (6) sanitising characters illegal in file names.
- Import-LIB-KiCad-Plugin already covers import-and-link for the general case but drops config writing, uses per-source libraries and a different path variable, and does not appear to enforce a `<Type>_<SubCategory>_<Manufacturer>` scheme or git commit flow. The personal tool's differentiator is convention enforcement plus a preview and git commit, not import per se.
- No evidence found of a tool that does duplicate detection against existing library contents; the Import-LIB README is silent on it.

### Gaps
- I found no 2025-2026 forum thread dedicated to SnapEDA pain points; the SnapEDA material is 2020-2023. 2026 evidence is mostly release notes of tools rather than user complaints.
- Ultra Librarian output specifics for KiCad 9/10 (file layout, 3D path format) not verified; no sample inspection done in this task.
- Impart GUI and SamacSys Library Loader current state not verified.

## 4. Does KiCad 10 (or the roadmap to 11) make a personal import tool obsolete?

### Takeaway
No evidence it does. KiCad 10.0.0 (released Mar 20, 2026) added no vendor-package importer, library-manager redesign for third-party zips, or drag-drop of zip files; its importers are for other EDA tools' designs. KiCad 11 is expected around Feb 2027 and its reported items include tabbed symbol/footprint editors and pin-to-pad maps, none of which import vendor ZIPs. One caveat: KiCad 10 introduced `.kicad_symdir` (one file per symbol) that a tool should account for.

### Cited Findings
- (Fact) KiCad 10.0.0 released March 20, 2026. Library items: STEP-only 3D libs, symbol editor pin table CSV import/export, multiple alternate body styles, footprint inner-layer objects, jumpers, PCB design blocks, importers for Allegro, PADS, gEDA/Lepton designs. No part-importer or library-manager redesign is mentioned. — [KiCad 10.0.0 release](https://www.kicad.org/blog/2026/03/Version-10.0.0-Released/), [CNX Software / AlternativeTo coverage](https://alternativeto.net/news/2026/3/kicad-10-released-with-track-tuning-revamp-windows-dark-mode-design-variants-and-more)
- (Fact) KiCad 11 is expected around February 2027. Reported KiCad 11 dev items (2026): SprintLayout, Diptrace, Eagle binary, Protrax/Tango, P-CAD design importers; match pad positions on footprint update; tabbed Symbol/Footprint editors (Jun 8); scalable footprints (Jun 21); pin-to-pad mapping (Jun 29). None concern vendor library ZIPs. — [Post-V10 New Features and Development News](https://forum.kicad.info/t/post-v10-new-features-and-development-news/66611)
- (Fact) KiCad 10 introduces `.kicad_symdir` support (folder with one `.kicad_sym` per symbol, analogous to `.pretty`). The official library repo uses it, packed to `.kicad_sym` for releases. The GUI cannot create/pick symdir libraries directly (GitLab #23601 saving, #23284 importing via GUI); users create the folder by hand and add via the library table; `kicad-cli sym upgrade --force foo.kicad_sym -o unpacked/foo.kicad_symdir/` was suggested for conversion. Windows illegal filename characters and small-file performance are caveats. Developer jmk stated (Apr 22, 2026) there is no new library structure and `.kicad_sym` remains the multi-symbol format. — [symdir thread](https://forum.kicad.info/t/v10-new-library-handling-kicad-symdir-unpacked/68546), [GitLab #23284](https://gitlab.com/kicad/code/kicad/-/issues/23284), [KiCad 10 migration epic](https://gitlab.com/groups/kicad/libraries/-/epics/14)
- (Fact) The Symbol Library Manager file picker still only shows `*.kicad_sym` files. — [GitLab #23284](https://gitlab.com/kicad/code/kicad/-/issues/23284)
- (Fact) The KiCad forum "Import Workflow" and zip-picking threads show the zip limitation existed through at least KiCad 7/8 with no official fix cited. — [Import Workflow](https://forum.kicad.info/t/import-workflow/45503), [Can not import .kicad_sym](https://forum.kicad.info/t/can-not-import-kicad-sym/48757/44)

### Inferences
- With no sign of an official vendor-package import feature in 10 or the 11 dev stream to date, the personal tool is unlikely to be obsoleted in the near term, though absence of evidence in the sources searched is not proof (GitLab issue tracker was not searched directly; search did not return a feature request).
- The symdir format is a forward-compatibility consideration: the tool currently targets a single `.kicad_sym` per library, which KiCad 10 still fully supports.
- Tabbed symbol editor and copy/paste between tabs (KiCad 11 dev) could reduce the manual copy/paste step but not path/field fixing.

## 5. Risks of a regex-based S-expression editor vs KiCad Python API / kiutils in 2026

### Takeaway
The KiCad IPC API/kicad-python needs a running KiCad and does not (as of KiCad 10) provide symbol-library editing, so it is not a substitute for file editing. kiutils is stale (last PyPI release Feb 2024, last upstream push July 2024) with documented KiCad 8/9 round-trip losses, so it is risky for KiCad 9/10 files. Regex or token-level editing of a few specific properties limits blast radius and avoids round-trip loss, but needs care with escapes, nesting and format versions.

### Cited Findings
- (Fact) kiutils (mvnmgrx) latest PyPI version 1.4.8 uploaded 2024-02-02; GitHub last push 2024-07-10 (repo not archived); description "for KiCad 6.0 and up". — [PyPI JSON](https://pypi.org/pypi/kiutils/json), [GitHub API](https://api.github.com/repos/mvnmgrx/kiutils)
- (Fact) Open kiutils issues/PRs include: hidden property fields become unhidden on save (#120, KiCad 8.0.4, open), `(effects (hide yes))` support PR (#125, open), "Incorrect parsing of symbol entryName in symbol library" (#129, May 2026, open), a PR validated on KiCad 10.0.1 adding `hide`, `show_name`, `do_not_autoplace` (#128, Apr 2026, open), and a v8/v9 round-trip fidelity PR closed unmerged May 2, 2026 (#127). — [kiutils issues API](https://api.github.com/repos/mvnmgrx/kiutils/issues?state=all&per_page=15)
- (Anecdote, third party) The author of a schema-free .NET S-expression library reported kiutils lost 89 `exclude_from_sim` tokens in one schematic; same failure mode (unknown tokens dropped) could apply to newer `.kicad_sym`. — [search result for SExpressions NuGet package](https://www.nuget.org/packages/SExpressions/)
- (Fact) A Rust crate `kiutils-rs` targets KiCad 10 primary and 9 secondary with lossless round-trip and unknown-node carriers; it is Rust, not Python; `.kicad_sym` support not verified. — [kiutils-rs docs](https://docs.rs/kiutils-rs)
- (Fact) The Python FlashPCB/kiutils fork has 0 stars and no documented differences from upstream. — [FlashPCB/kiutils](https://github.com/FlashPCB/kiutils)
- (Fact) kicad-python (kipy) 0.8.0 released 2026-08-30; requires KiCad 9.0+ with the API server enabled and a running instance; some features require KiCad 10 / 10.0.1; SWIG bindings removed in KiCad 11. — [kicad-python PyPI JSON](https://pypi.org/pypi/kicad-python/json)
- (Fact) The IPC API controls a running KiCad instance over protobuf/NNG. — [KiCad IPC API dev docs](https://dev-docs.kicad.org/en/apis-and-binding/ipc-api/)
- (Fact, dev post Mar 21, 2026) `kicad-cli api-server` starts a headless IPC session and output jobs are exposed via the IPC API; kipy PyPI releases are stable-only. — [Post-V10 news thread](https://forum.kicad.info/t/post-v10-new-features-and-development-news/66611)
- (Anecdote, third-party MCP/tool docs, unverified against official docs) In KiCad 10 the IPC API has schematic types but no schematic commands, and `get_schematic()` is tagged KiCad 11; symbol-library work is file-based. — [kicad-mcp project docs surfaced by search](https://cdn.jsdelivr.net/gh/mixelpixx/KiCAD-MCP-Server@main/README.md)
- (Fact) `kicad-cli sym upgrade` exists and can rewrite a symbol library into the current format; `kicad-cli sym` help lists only `export` and `upgrade`. — [symdir thread](https://forum.kicad.info/t/v10-new-library-handling-kicad-symdir-unpacked/68546)
- (Fact) Import-LIB-KiCad-Plugin (a maintained Python importer) had to fix real format issues in 2026: KiCad 9/10 symbol data lost on import, SymbolPin v9 hide token, hidden-field loss. This is evidence that format drift breaks naive parsing/writing. — [Import-LIB releases API](https://api.github.com/repos/Steffen-W/Import-LIB-KiCad-Plugin/releases?per_page=5)
- (Fact) KiCad 10 migration epic notes `kicad-library-utils` needs file-format updates and cpresser says it will lose packed-`.kicad_sym` features soon. — [symdir thread](https://forum.kicad.info/t/v10-new-library-handling-kicad-symdir-unpacked/68546), [epic](https://gitlab.com/groups/kicad/libraries/-/epics/14)

### Inferences
- kiutils is not a safe default for rewriting KiCad 9/10 symbol libraries: it is unmaintained upstream since mid-2024, has open bugs on hidden fields and `entryName`, and no KiCad 10 claim. If used at all, it should be gated by a round-trip diff test on real KiCad 10 files.
- The IPC API route is ruled out for this tool: it requires a running KiCad GUI/server, and symbol editing is not exposed (per unofficial sources).
- The regex route has lower fidelity risk for narrow edits (rename symbol, set Footprint property, rewrite `(model ...)` path) because untouched text is preserved byte-for-byte, which is also friendly to git diffs. Risks: nested parentheses and quoted strings containing parens, `\"` escapes, multi-symbol libraries where regexes bleed across symbols, `extends` (derived) symbols that reference a parent by name, KiCad 10 symdir, and version-token differences (KiCad 6 vs 9 property/hide syntax). A paren-balanced tokenizer (not a full typed parser) combined with a post-write validation using `kicad-cli sym upgrade` or a sexpr re-parse is a middle path that the evidence supports but does not directly prescribe.
- Validation tool candidates for CI-style checks: `kicad-cli` (ships with KiCad); not established whether it can lint a single `.kicad_sym` beyond upgrade/export.

### Gaps
- Could not read kiutils CHANGELOG or verify whether any maintained fork supports KiCad 10 symbol formats; the 89-token claim is from a competing library's author.
- Official docs for IPC API did not state symbol editor coverage; the "no schematic commands" claim is from third-party MCP projects.
- No KiCad 10 `.kicad_sym` format version number or spec was retrieved (the file-format docs were not fetched).
