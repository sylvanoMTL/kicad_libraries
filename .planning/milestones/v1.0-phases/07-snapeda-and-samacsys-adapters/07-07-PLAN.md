<objective>
Close the core of UAT gap G-07-2. A separately downloaded SnapEDA 3D model, either a bare .step/.stp/.wrl or a zip holding it, can be added to an open import and installs linked as `${CUSTOM_3DMODEL_DIR}/<file>`.

Owner decision (UAT G-07-2, 2026-10-23): this overrides the carried-forward 07-CONTEXT rule "SnapEDA is the no-model case", PROJECT.md Out of Scope and REQUIREMENTS FMT2-02 (v2). Plan 07-09 updates those docs. A SnapEDA CAD zip opened on its own is still the no-model case. The new part is a second intake source added to an open import.

Root cause being fixed (.planning/debug/snapeda-separate-3d-model.md): intake is single-source end to end. open_package takes one zip or folder, ImportCandidate.models is filled only from that Package, a model-only zip is refused (intake.nothing_found), a bare .stp is refused (intake.unsupported), and ImportDialog holds one package with no way to add a model. Case G of the diagnosis showed that a model from a second Package attached with dataclasses.replace already flows through build_plan / apply_plan. So the frozen plan contract (InstallPlan, FileOp, planner, applier, commit_plan, preview) stays unchanged, and only intake and the dialog grow.

Design choices (Claude's discretion, recorded here):
- open_model_source lives in package.py beside open_package and reuses _open_zip / _stage_zip / _prescan through a new keyword-only `kinds` filter. open_package keeps its behaviour, with the default filter meaning "all stage kinds".
- Byte budget is per package. Each model source gets its own _Budget and staging folder, so MAX_MEMBER_BYTES / MAX_TOTAL_BYTES apply to each source separately. Each source is an explicit user pick, staged outside the repo and removed on Change... or close. Bare files are never staged. Accepted as T-07-26.
- attach_models lives in adapters/base.py, next to locate and _check_model, so the magic check is the same function and no private name crosses modules.
- The dialog keeps a list of attached model packages (self._model_packages). Attaching again adds models, never replaces them, so no package is closed while a build may still read it. The combo already lets the user pick among models or choose "No model".
- The magic check runs in attach_models for every model of the second source, staged or bare, exactly as locate runs it for package models.

Purpose: UAT test 2 (G-07-2) passes. The SnapEDA CAD zip plus its separate model download installs a linked 3D model, with no hand-editing.

Output: open_model_source, attach_models, the dialog's Add 3D model... tracer path, a synthetic model-download fixture, and the intake and attach test suites.
</objective>
