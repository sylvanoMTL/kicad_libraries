<objective>
Tracer for UAT gap G-07-5. An unusable 3D model source is an ERROR, shown in red, that blocks Install Part until the user removes it or adds a usable model. This plan proves the whole path on the refusal of a bare file. Plan 07-13 (gap wave 2) adds the other rejection rules, the clears and resets, and the help and doc rewording. Together the two plans close G-07-5. They were one plan until the plan-checker found it near the per-plan context budget (2026-10-24). The split moved tasks between plans and did not change their content.

User decisions (07-UAT.md G-07-5 `decisions:`, 2026-10-24, binding; the plan that implements each is in brackets):
- An unusable model source shows a red (theme.ERROR) plain-text error note and blocks Install through a blocking Reason that targets the model row. [07-10]
- Read failures (the model worker fails) block too. [07-13]
- A zip that holds any unusable model file is rejected as a whole; nothing from it is attached. [07-13]
- A Remove button clears a rejected source only. Detaching a successfully attached model is out of scope. Add 3D model... remains the way to add another source. [07-10]
- INFO duplicates stay non-blocking. [07-13]
- This supersedes the 07-08 must-have "Refused/empty source leaves candidate and row unchanged; reason as plain-text amber note". 07-13 Task 2 rewords it.

Root cause (.planning/debug/unusable-model-source-not-blocking.md): this is a design gap, not a regression. Plan 07-08 specified that a refused model source is closed and forgotten. It never reaches the candidate, FormStatus or blocking_reasons, so it cannot block Install. The core already returns Severity.ERROR intake.no_model_in_source, but the dialog hard-codes the amber tone in _on_model_attached and _on_model_failed. The greyed-out Install in UAT test 5 came from an unrelated unresolved symbol conflict (the part was already installed in live Custom/ during test 3), not from the refusal.

Design choices (Claude's discretion, recorded here):
- The dialog keeps only the rejected source's file name and its first ERROR Issue (`RejectedModel`). The rejected package is still closed at once, so a rejection holds no file handle or staging folder.
- The reason text is `Error: <first ERROR text>`, the same prefix as plan errors, placed right after the build-failure or plan-error block in blocking_reasons.
- The "model" reason target is the Remove button, the control that fixes the reason. No amber field frame is added for the model row, so theme.py does not change: theme.ERROR already exists and is already imported by import_dialog.py.
- The duplicate rule and the partly-bad-zip error code are recorded in 07-13, which implements them.

Purpose: with 07-13, UAT test 5 passes. A bad model file can no longer be overlooked before Install, and the user can recover from it in place.

Output: the form rule, the dialog's rejected-source state, Remove and the red note, and their tests.
