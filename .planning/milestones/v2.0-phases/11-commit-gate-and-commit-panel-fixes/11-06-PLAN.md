## Trust Boundaries

| Boundary | Description |

| work tree bytes -> identical set | file bytes on disk decide which planned files are already in HEAD |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-12 | Repudiation | timeout reporting | medium | mitigate | HEAD is read before and after a failed commit; a moved HEAD is reported as a commit with its hash, never as "nothing was committed" (`test_commit_timeout_after_head_moved_reports_commit`, real slow-hook test) |
| T-11-13 | Tampering | parent bump during a leftover git | medium | mitigate | After a late commit no second git write starts (no unstage, no parent commit); the user gets the manual parent command instead (D-12) |
| T-11-14 | Tampering | identical-file handling | low | mitigate | Only files proven equal to HEAD by hash are downgraded to INFO; an extra committed file or a planned file missing for any other reason stays the `commit.unexpected_files` ERROR |
| T-11-SC | Tampering | npm/pip/cargo installs | low | accept | No package is installed or upgraded by this plan |

Threat IDs: `T-11-SC` is the reserved per-plan supply-chain row, exempt from the T-11-NN uniqueness rule and kept in every plan. T-11-17 is retired (dropped while drafting) and is not reused.
