<objective>
Close two migration-window gaps found in the owner's live UAT on 2026-11-12.

**G-13-1-a (major):** with the main checkout's venv (Python 3.11.3, PySide6 6.10.2) the app does not start: `NameError: name 'CommitPlan' is not defined` at `migration_dialog.py:338`. `_CommitStepHost.start(self, plan: CommitPlan)` (line 338) and `_CommitStepHost._on_probe_done(self, worker: TaskWorker, probe: CommitProbe)` (line 373) annotate parameters with two names the module never imports. Python 3.10-3.13 evaluate parameter annotations when the class body runs; Python 3.14 (the repo venv, the only interpreter the suite runs on) defers them (PEP 649/749), so the defect never showed. Diagnosis: `.planning/debug/py311-commitplan-nameerror.md` (an AST scan of all 79 files found exactly these two sites; with both imports added all 78 modules import on 3.11).

**G-13-1-h (major):** `migration_dialog.py:752` connects only `_library_combo.lineEdit().textEdited`. Picking a library from the dropdown list emits `currentTextChanged`/`textActivated` but not `textEdited` (offscreen probe in `.planning/debug/imu-suggested-atomic-timer.md`), so a list pick is never recorded in the plan or the draft. This weakens the "owner corrects it in the preview" path that D-01 relies on, and plan 13-26 needs a list pick to confirm a guessed library.

Purpose: the app must start on every supported Python (3.10+), and the owner's library pick must stick however it is made.
Output: two imports and one signal connection in `migration_dialog.py`; a new regression gate `tests/test_annotations_resolve.py`; one Qt test in `tests/test_migration_dialog.py`.

Scope note: the 3.14 suite cannot import on 3.11, but it can read every annotation, which raises the same NameError on 3.14 (debug evidence 2026-11-12T18:00). That is the gate this plan adds; no CI or second interpreter is introduced. `eval_str` stays False on purpose: modules with `from __future__ import annotations` (for example `importer/migration/symbols.py`, whose `FootprintsOutcome` hint is a deliberate string) never evaluate their hints at import on any version, so they are not this bug class and need no exemption.
</objective>
