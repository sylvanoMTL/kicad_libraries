<objective>
Close UAT gap G-12-23: "Use persistence so that if we close/open, it retains the paragraph that was browsed and display it, and expand the section on the left panel. (I think selecting and expanding the node would do the job)". Root cause (12-UAT.md, binding): the guide has no saved place. `HelpDialog.__init__` opens on the first menu item whenever no topic is given and never reads a saved key; nothing saves the current key (settings.py has no help key, `_on_topic_selected` writes nothing, there is no close hook); and the main window built a new guide per F1, so the place was lost on close (plan 12-18 now keeps one shared guide). Saving on close is not enough: Escape and a deleted parent fire no close event, so the key must be saved each time a page or section is shown. Restore already works through `show_topic(key)`.

This plan saves the owner's own moves through new settings helpers, restores them when the guide opens with no topic, keeps explicit topics (the import window's Importing Parts) out of the memory, and makes the main window's Help and F1 reopen the owner's place.

Output: settings helpers, HelpDialog changes, `show_guide` in the main window, a CLAUDE.md line, tests.
</objective>

## Choices made here (planner's discretion)

- **What counts as an owner move.** A change of the menu's current item that does not happen inside `show_topic`, the constructor's fallback selection, or `show_remembered`. A counter `self._quiet` is raised around those programmatic selections (with try/finally, so a nested group-to-first-child selection inside them stays quiet). A click on a group header saves the first page it opens; a key press in the menu saves too.
- **Restore API.** `HelpDialog.show_remembered(self) -> None`, public, docstring: show the place the owner last chose, quietly; tries the saved key with `show_topic`, then its page part (the text before "#"), then the first menu item. The constructor calls it when `topic` is None; with a topic it calls `show_topic(topic)` and falls back to the first item, both quiet.
- **Main window rule (completes plan 12-18's `show_guide`).** With a topic: `show_topic(topic)` as before (quiet, not saved). With no topic: when the guide already exists and is hidden, call `show_remembered()` before showing it; a new guide restores in its constructor; a visible guide is only raised, so a page being read is never pulled away.
- **Saved value checks.** `load_help_topic` returns the value only when it is a non-empty str; any other stored type (a number, a list) reads as None. Keys are never trusted beyond that: an unknown key simply fails `show_topic` and falls back.
