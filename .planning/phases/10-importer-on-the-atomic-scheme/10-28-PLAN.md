<objective>
Close review warning WR-05 and record the three gap-closure fixes.

`MainWindow._finish_post_install` has two branches. After an install that creates a library, it calls `add_library_entries` with the footprint pair only when the footprint library is new. A shared `Atomic_Footprints` that already exists on disk but is missing from fp-lib-table therefore gets neither an entry nor the "Press Generate Tables" hint that the existing-library branch gives. This happens after regenerated or hand-edited tables, or on a first install on another machine. The new symbol then links `Atomic_Footprints:<FP>`, and KiCad shows an unresolved footprint library. The fix is the review's: pass the footprint pair whenever the footprint library is a folder of this repo. `add_library_entries` leaves a table that already lists the nickname alone, so this is idempotent.

This changes the plan 10-11 truth "the footprint library goes to fp-lib-table only when that library is new and lives in the repo". It now goes whenever it lives in the repo, and a table that lists it is left as it is. Plan 10-11 is executed and is not edited.

The plan then runs the combined suite, records CR-01 (plan 10-26), WR-02 (plan 10-27) and WR-05 (this plan) as fixed in 10-REVIEW-DISPOSITION.md, and updates check 6's expected text in 10-VERIFICATION.md so the owner's checklist is not stale. That is why it runs after both wave-18 plans.

Purpose: a part linked into Atomic_Footprints resolves in KiCad right after install, whichever machine or table state it was installed on (LIB-06, D-15).
Output: a one-condition change with a comment above it in `main_window.py`; new tests in `tests/test_main_window_import.py`; the updated disposition record; check 6's new expected text in 10-VERIFICATION.md.
</objective>
