<objective>
Close UAT gap G-10-1 (review finding WR-06, severity major). When a vendor footprint's own text names no package family, build_plan borrows one from official KiCad footprints through `_agreed_family_texts`. A leading-letters-only tie (score 30) passes today whatever the vendor part's size. On KiCad 10 the 6-pin codes SON50P150X150X60-6N and SON65P200X200X80-6N tie on two SON-8 footprints, so "SON-8" is written into the footprint description, the generated tags and the symbol keywords. This breaks D-28 ("nothing is guessed").

The fix follows the owner decision of 2026-10-29 (UAT test 1: "fix WR-06 with the pad-count filter, as recommended"), in the symmetric form the owner chose. A leading-letters-only tie counts only the official footprints within one pad of the vendor footprint's pad count. Full-code ties are not filtered, and the agreement rule of 10-26 then runs on what is left.

Purpose: generated footprint text and keywords carry only package facts that fit the vendor part (FLD-03, FLD-01, D-28).
Output: the pad filter in `planner.py` (helper, call site and comment), a public `FULL_CODE_SCORE` in `footprint_index.py`, pad-aware fixtures plus new family tests in `tests/test_generated_text.py`, and WR-06 recorded as fixed in `10-REVIEW-DISPOSITION.md`.

Human checks: no expected text of the end-of-phase checks changes. Check 3 keeps "WSON-6 2.1x2.1 mm, 0.65 mm pitch, TI DQK0006B".

Commands: run every command in this plan (the `<automated>` blocks, the acceptance criteria and the verification section) in Git Bash, that is the Bash tool, from the repository root. Do not run them in PowerShell. They use the POSIX inline assignment `QT_QPA_PLATFORM=offscreen env/Scripts/python.exe ...`, `grep` and `git`, which Git Bash provides. `env/Scripts/python.exe` is the project's Windows CPython venv (PySide6 needs it), and Git Bash runs it by that relative path.
