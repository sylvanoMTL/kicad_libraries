## Owner decisions (binding)

- G-12-9 (2026-11-03): a toolbar at the top of the import window, visible on every page (open-package start page, edit/preview page, result page). It holds a Help action with the plain label "Help", a tooltip and the F1 shortcut. Help opens HelpDialog on "Importing Parts" and the import window stays open. QDialog has no built-in toolbar area, so the QToolBar goes into the dialog's outer layout above the page stack. The toolbar holds the Help action only. No other button moves: "Choose another package...", Install Part, Cancel and the result page's Close stay where they are, because each of them belongs to a single page.
- Standing rule: plain words in all user-facing text (no raw field names, code identifiers or tool names).

## Choices made here (planner's discretion)

- **Non-modal Help window, parented to the import dialog.** `_on_help` calls `show()`, never `exec()`. A window that is a child of the window-modal import dialog is not blocked by it. A window parented to the main window would be blocked, and so would its Close button. Without a nested `exec()` loop, a close that waits in Finishing can still run while the guide is open. The owner can read the guide and edit the part side by side.
- **One Help window per import window.** It is kept in `self._help_dialog` and reused: a second Help or F1 calls `show_topic` again and brings it to the front. `_shutdown` closes it, so it never outlives the import window.
- **F1 is the QAction's shortcut** (window context, the same `QKeySequence("F1")` the main window uses). No separate shortcut object is added. The main window's F1 lives in another window, so the two never clash.
- **Help stays enabled in every state.** The toolbar is outside the stack, which Finishing disables, and outside the inputs an install locks. The guide is read-only.
- **The toolbar** has no stylesheet (UI-01). It uses the platform's standard help icon with the text beside it, so the word "Help" always shows. It is not movable.
