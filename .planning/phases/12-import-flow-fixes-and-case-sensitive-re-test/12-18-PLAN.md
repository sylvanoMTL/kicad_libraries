<objective>
Close UAT gap G-12-22: "is there a way to be able to use the main window while the user guide is opened? same for the help" (restated: "a way to have the user guide and help open at the same time as any window, with possibility to browse it"). Root cause (12-UAT.md, binding), three parts: (1) `MainWindow._on_help` runs the guide through a blocking exec, which makes it application-modal and builds a new guide per F1; (2) the import window's guide is its child, so any window-modal child of the import window (content view, Check Atomic Parts) blocks it, and `_shutdown` closes it with the import window; (3) a guide parented to the main window is blocked by the import window and the Loading Libraries window, only a parentless guide escapes window-modal dialogs, application-modal dialogs (the path-variable question, the KiCad-open box, Restore Backup, About) block even a parentless guide, and a parentless visible guide keeps the app running after the main window closes.

This plan makes the User Guide one shared parentless, non-modal window owned by the main window, used by the main window's Help and F1 and by the import window through a callable, and closes the guide with the main window (root causes 1, 2 and the parentless and closing parts of 3). Plan 12-20 (wave 5) makes the four main-window dialogs window-modal, proves the guide beside the Loading Libraries window and updates the Help text; G-12-22 was split into these two plans so each stays well inside the per-plan context budget (checker revision).

The system file pickers stay application-modal and may block the guide while one is open: the owner approved this exclusion after the plan check (12-UAT.md Owner Decisions, "G-12-22 (approved exclusion, asked after plan check)", commit d2c45a7), choosing "No, pickers may block" over converting them to Qt window-modal pickers. The plan converts no picker, and the summary names this approved exclusion.

The plan supersedes the 12-14 prohibition that `main_window.py` keeps its blocking guide call and that the import window parents its guide; the owner's G-12-22 report and decision replace those 12-12/12-14 rules.

Output: changes to `main_window.py` and `import_dialog.py`; tests in the three window test files.

## Choices made here (planner's discretion)

- **Checked in an offscreen probe (2026-11-04).** A parentless QDialog keeps a null transient parent when shown, also while a window-modal dialog is active. Window-system clicks reach it while a window-modal dialog of the main window is open (also one run through exec), while a window-modal child of that dialog is open, and while a window-modal progress dialog is open; an application-modal box drops them. So the guide is parentless (this plan), and the four dialogs keep their blocking exec but become window-modal first (plan 12-20).
- **Shared guide API on MainWindow.** `self._guide: HelpDialog | None = None`. `_guide_window()` creates `HelpDialog()` once (no parent); before its first show it is moved so its frame is centred on the main window's frame, and `HelpDialog.showEvent`'s `fit_window` (plan 12-14) then keeps it inside the free area. `show_guide(topic: str | None = None)`: get the guide, call `show_topic(topic)` when a topic is given, then `show()`, `raise_()`, `activateWindow()`. `_on_help` calls `show_guide()`. Plan 12-19 adds the remembered place to the no-topic path.
- **Import window hook.** `ImportDialog(..., show_guide: Callable[[str], None] | None = None)`. With the hook, Help and F1 call `self._show_guide(_HELP_TOPIC)` and nothing else. Without it, the import window keeps a parentless fallback guide in `self._help_dialog` (created with `topic=_HELP_TOPIC`, later `show_topic(_HELP_TOPIC)`), shows, raises and activates it, and never closes it in `_shutdown`. The 12-12 comment about the guide being a child of the window-modal dialog is replaced.
- **Start commit (checker revision).** Before its first edit, Task 1 records the plan's start commit with `git rev-parse HEAD` and writes the hash into the summary as "Start commit: <hash>"; Task 2's no-picker check diffs against that hash.
- **Tests' cleanup.** The import-window tests now leave parentless guides behind; an autouse fixture in tests/test_import_dialog.py closes and `deleteLater`s every top-level HelpDialog after each test. The main-window tests close the window (which closes the guide) or close the guide directly.
