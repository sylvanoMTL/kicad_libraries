(2) The initial size limited to the screen's free area, with the minimum shrunk if needed, so the whole window is on screen at 100% and 200%. - Standing rules: plain words in all user-facing text. Verification covers 100% and 200% Windows display scale. Earlier decisions stay: D-06 (close waits in Finishing, never joins a worker on the GUI thread) and D-10 (an install cannot be cancelled; no default button, Enter never installs).

## Choices made here (planner's discretion)

- **Where the start Cancel goes.** It sits at the bottom right of the start page, in its own row under the centred column. That is the same corner as the edit page's Cancel, so Cancel is always in one place. It stays enabled while a package is read: `reject()` then waits in Finishing, exactly like the X. The result page already has Close, so it gets no new button.
- **Sizes.** The start page wants 640x440. The column is at most 560 wide plus 16 px margins on each side, and 440 fits even the 20-issue state, whose layout minimum was measured at 330 high. The edit page wants 1100x720, today's size. A size is bounded by the screen's free area less a frame allowance of 16x40 (title bar and borders, used until the real frame is known). It is never made smaller than the layout's minimum. When the screen is smaller than that minimum, the window keeps the minimum and its title bar stays on screen.
- **200% in automated tests, modelled in logical pixels.** Qt lays widgets out in logical pixels, and at 200% scale fonts and metrics in logical pixels are about the same as at 100%. So a free area of 960x492 (a 1920x1080 screen at 200% with a 48 px taskbar) models the 200% layout at device-pixel ratio 1. The tests reach it through a module-level `screen_area(widget)` seam. The human check covers the real 200% display.
- **The test environment's default screen.** The offscreen test platform has one 800x800 screen. Without help, every existing edit-page test would run at the edit page's minimum width (854) instead of 1100. An autouse fixture in `tests/conftest.py` therefore makes `screen_area` return a Full HD 100% free area (1920x1032) whenever the import dialog module is loaded, so the edit page keeps 1100x720 in every existing test. It looks the module up in `sys.modules` and never imports Qt itself, so Qt-free test modules stay Qt-free.
- **The minimum follows the page.** A QStackedWidget's minimum is the largest of all its pages, so the start page could never be narrower than the edit page's 822. `_show_page` gives the current page the Preferred size policy and every other page Ignored, which drops hidden pages from the minimum. This was checked in an offscreen probe: the start minimum became 416x204, the edit page's 854x256 once shown, and the splitter kept 426:638 at 1100 wide.
- **Grow and shrink.** Every page switch goes through `_show_page(page)`. Entering the start page from another page stores the current size as the edit size and shrinks to the start size. Entering the edit page grows to the stored edit size, initially 1100x720. The result page replaces the edit page in place and keeps its size. Switching to the page already shown changes no size, so a user's resize on the same page is kept. The window keeps its centre and is then moved fully into the free area, but only while it is visible: moving a hidden window would stop Qt from centring it over the main window on first show.
