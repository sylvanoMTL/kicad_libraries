<objective>
Close UAT gap G-12-12 (cosmetic, UAT test 12): "You can still reduce the size and have the browse and cancel in the same layout grid." Root cause (12-UAT.md, binding): the start page has a fixed 640x440 size (`_START_SIZE`) that is taller than its content (the layout wants about 476x316), and the stretch between the centred column and the separate bottom Cancel row absorbs the extra height, leaving a ~144 px band between the Browse row and Cancel. `_fit_size` only clamps to the screen, never to the content, and the "room for the issue list" rationale does not hold because the window grows by itself through its layout minimum when issues show.

This plan moves Cancel into the Browse row, sizes the start page from its content at width 640, gives the Downloads line and the reading box one shared slot so the height does not jump, and refits the window when the issue list shows or clears.

Purpose: the owner's sketch shows a compact start window of about 634x340 with Cancel on the Browse row.
Output: changes to `import_dialog.py` and the Importing Parts Start text in `help_dialog.py`, new and updated tests.
</objective>

## Choices made here (planner's discretion)

- **Where Cancel goes.** At the right end of the Browse row inside the centred column: Browse zip..., Browse folder..., a stretch, Cancel. The row layout becomes the attribute `self._start_buttons`. On the edit page Cancel stays at the bottom right, right of Install Part, so Help names both places.
- **Start height.** `_START_WIDTH = 640` replaces the fixed start size. `_start_size()` activates the dialog's layout and returns width 640 and a height of `layout.totalHeightForWidth(640)` (the layout's height for that width, margins included; word-wrapped labels make it height-for-width), falling back to `layout.totalSizeHint().height()` when the layout has no height-for-width, and never below `minimumSizeHint().height()`. An offscreen probe (2026-11-04) gave 258 for the current content with the Downloads line hidden; with Cancel moved up and the shared slot the expected result is roughly 300. Tests assert relations, never this number.
- **One shared slot.** A container `self._offer_slot` whose QGridLayout (margins 0) holds the Downloads row and the reading box in the same cell (0, 0). Both keep `retainSizeWhenHidden` on their size policy, so the slot is always as tall as the taller of the two, whether the lookup is pending, the Downloads line shows, or a package is being read. Their own show/hide logic (`_set_reading`, `_on_offer_found`) is unchanged, so `_offer_row.isVisible()` and `_reading_box.isVisible()` keep their meaning for the existing tests.
- **Refit points.** The start size is applied in `__init__`, at first show (when the start page is current), when `_show_page` enters the start page from another page (plan 12-13's rule: switching to the page already shown changes no size), after `_show_start_issues` fills the issue list, and after `_hide_issue_box` clears it while the start page is current. Each goes through the existing `_fit_to_screen`, so the screen bound and the never-below-minimum rule of `fit_window` stay the only sizing path.
