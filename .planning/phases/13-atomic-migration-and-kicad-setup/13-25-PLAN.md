<objective>
Close the matching half of gap G-13-1-f: in the owner's live run the migration filed ICM-42688-P (a 6-axis MEMS IMU from `IC_IMU_TDK`) into `Atomic_Timer`. Diagnosis: `.planning/debug/imu-suggested-atomic-timer.md`. `siblings.family_prefixes("ICM-42688-P")` yields only `["ICM"]` because its regex stops at the hyphen; KiCad 10's stock symbols starting with ICM are four Intersil timers in Timer and two InvenSense IMUs in Sensor_Motion, so `pick` decides Timer 4:2; `suggest.suggest_library` returns that stock vote before `categories.classify` runs, and the Sensor_Motion rule lacks "6 axis" / "motiontracking" anyway. 13-CONTEXT (Claude's Discretion, "Research defaults") accepted this mis-suggestion at planning time; the owner has now asked for it to be fixed (decision 2026-11-12: fix both the matching and the visibility).

This plan fixes the matching; plan 13-26 makes the remaining guesses visible and confirmable in the migration window. The two are split because they touch different subsystems (importer suggestion engine vs migration gate and window) and plan 13-26 builds on the `weak` flag defined here.

Chosen route (each item is one of the gap's `missing:` options, stated here rather than decided silently):
1. **Separator-aware part-number steps** (the "keep ICM- / ICM-4 steps before bare letters" option): a single `-` or `_` between the leading letters and the first digit run is kept, giving `ICM-42688`, `ICM-4`, `ICM-`, `ICM`. A separator followed by a letter (`ATXK-H14`, `NORA-W106`) adds no step, so every existing prefix expectation except the new cases stays as it is.
2. **A weak vote yields to the description** ("let the description outrank a split stock vote"): `SiblingPick.weak` = decided on the bare letters, or by less than three quarters. Three quarters keeps clear real votes strong (KiCad 10's CSD family is 75 Transistor_FET to 2 Diode) while 4 of 6 is weak. A weak vote is checked against `classify`; the own-then-stock order of Phase 10 D-01 is not changed, so a weak own vote does not fall through to the stock vote.
3. **Motion words** in the Sensor_Motion rule, and the rule moved above Sensor_Magnetic so a 9-axis IMU that mentions its magnetometer is still a motion sensor.

The importer shares `suggest_library`, so Import Part gets the better matching too; its window shows no new mark (the visible "check this library" line is migration-only, plan 13-26).

Purpose: the suggestion lands on the right library from the part's own data, and a coarse vote never silently beats the part's own description.
Output: changed `siblings.py`, `suggest.py`, `categories.py`; a KiCad-10-shaped migration stock fixture; updated and new tests.
</objective>
