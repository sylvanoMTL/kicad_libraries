Close gap G-13-1-g: in the live run the migration window, opened with `dialog.open()` and therefore window-modal, blocked the main window, whose Destination box still pointed at a deleted throwaway folder; the Result view shows no Destination, `generate_requested` is a bare signal, and `_on_generate` reported "Destination folder does not exist" only to the blocked main log, so the owner had to close the migration window and generate from the main window. Diagnosis: `.planning/debug/result-view-destination.md` (verified offscreen: WindowModal, `WindowBlocked` until close, no Destination widget in the Result view, silence in the dialog on a missing or blank Destination; trigger: `_populate_dest_combo` restores a deleted folder from `dest_history` without a check).

Owner decision (2026-11-12, given to this planning round): **option A** — show the Destination with Browse... in the Result view, keep the main window as the single source of truth, and mirror the Generate outcome into the Result view, plus skip non-existent folders when the Destination history is restored. **Do not make the window non-modal.**

Chosen details (stated, not decided silently):
- The dialog never owns a Destination: `set_destination(text)` shows what the main window has; Browse... only *asks* the main window to change it (`destination_changed(str)`), which echoes the result back. So both Generate and the pin action (whose pins come from the tables in the Destination folder, 13-CONTEXT Claude's Discretion) always use the folder shown.
- No automatic folder prompt on Generate: a blank or missing folder is shown up front with an amber note and Browse... next to it, and Generate's own refusal is mirrored. One way to change it, always visible.
- The history filter is display-only (an unplugged drive may come back); the saved history is not rewritten.

Purpose: the owner can see and change where the tables go without leaving the migration Result view.
Output: Result-view Destination row and status line, main-window wiring and mirror, the existing-folder filter, tests, docs, and the one full-suite run for all six gap plans.
