<objective>
Close verification gap CR-01: the migration's 3D-model rename pass checks each candidate name against a frozen snapshot of the pre-migration inventory that never grows, so two model groups in one run can both be renamed to the same file — one model's bytes are overwritten, both originals are deleted, and the transaction reports success. This plan makes the run's own decisions part of the name registry, turns a collision into a blocking strip line the owner must resolve before Run, and adds the structural backstop in the applier so no plan with two writes for one path can ever execute.

Purpose: the phase's truth 2 ("one transaction with rollback, every Footprint field and model path rewritten") and MIG-02's "every failure as an edit-box line" are both false for this failure mode today — there is no failure to roll back from, the loss is baked into a successful commit. This is the last blocking gap of Phase 13 and the owner's live migration (the human_verification item) must not run before it is closed.
Output: the claimed-name registry and two new blocking issues in `footprints.py`, the duplicate-write invariant in `applier.py`, and seven regression tests.

Scope note (gap-closure contract): tasks 1 and 2 are the gap's two `missing` items plus the applier artifact the gap names. Task 3 is declared co-located scope: the footprint-name path can queue the same duplicate-write pair when the owner resolves an in-run name clash with Overwrite, so without it Task 2's structural refusal would surface at Run time in a flow the strip called clean. The open review items WR-01, WR-02 and IN-01 are not verification gaps and are not touched here.
</objective>
