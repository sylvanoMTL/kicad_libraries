# Phase 05 - UI Design Contract

> Visual and interaction contract for the Import Part dialog, the main-window entry points (menu, toolbar button, drag and drop) and the post-install behaviour. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> This is a **PySide6 / Qt Widgets desktop app**, not a web frontend. There is no CSS framework, shadcn or Tailwind. Every value below is expressed in Qt terms (layout margins and spacing in px at 96 DPI, `QFont` point sizes, hex colors applied through palette roles or stylesheet strings). Behaviour decisions come from `05-CONTEXT.md` (D-01..D-19, locked) and are not re-opened here. This file adds the visual values and copy that CONTEXT left to Claude's discretion, and marks each one **(default)** when it is a choice made here rather than a locked decision.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (native Qt Widgets; no web design system, no shadcn) |
| Preset | not applicable |
| Component library | Qt Widgets via PySide6 6.12.0 (native Windows style; local stylesheet strings only where listed below) |
| Icon library | none. Text glyphs only, always in the text color of the row: `⚠` warning, `✖` error, `✓` success, `↺` restore default, `→` rename arrow. No image assets, no emoji font. |
| Font | System UI font at the platform default size (Segoe UI 9pt on Windows 11) for everything except code-like text. Monospace: `Consolas` 9pt (same as `LogPanel`). |

Existing conventions that this phase reuses and must not contradict:

- Primary button style from `main_window.py` `_build_ui` (accent fill `#0078D4`, white bold text). Its existing padding `6px 16px` is replaced by `8px 16px` through `PRIMARY_BUTTON_QSS` (see Shared theme module); the Generate Tables button is updated with it.
- `LogPanel` level colors and `Severity.value` as the color key.
- Two `QTreeWidget` panes with `setAlternatingRowColors(True)`.
- Window-modal dialogs, `QDialogButtonBox`, `Browse...` button labels (see `BackupDialog`).
- Qt enums fully qualified; `blockSignals` / `_updating` guards with try/finally.

### Shared theme module (new, fold-in of the Phase 2 UI review)

Create `kicad_lib_manager/widgets/theme.py` (no Qt imports needed; plain constants and one stylesheet string). It is the **only** place color, spacing and the primary-button stylesheet are defined. `log_panel.py`, `library_table.py`, `help_dialog.py` and the new dialog import from it. `main_window.py` imports it for the toolbar button and the Generate button.

| Constant | Value | Notes |
|----------|-------|-------|
| `AMBER` | `#8A5200` | Warning text, blocked-field border, unresolved conflict bar. Replaces every `#CC7700` literal (`log_panel.COLORS["warning"]`, both `QColor("#CC7700")` in `library_table.py`, the help-text span). About 6.4:1 on white. |
| `AMBER_TINT` | `#FFF8E1` | Background of the blocking-reason strip and the KiCad-running notice (same tint the help dialog already uses). |
| `ERROR` | `#CC0000` | Error text, destructive action. About 5.9:1 on white. |
| `ERROR_TINT` | `#FDECEA` | Failure banner background, removed lines in a diff. |
| `SUCCESS` | `#007700` | Success text, `+` new-file glyph, resolved-conflict bar. |
| `SUCCESS_TINT` | `#E6F4EA` | Added lines in a diff. |
| `ACCENT` | `#0078D4` | See Color section for the reserved-for list. |
| `LINK` | `#0057A0` | Clickable blocking-reason links (same blue as help headings). |
| `MUTED` | `#595959` | Secondary text, `=` unchanged glyph, disabled-button text. About 7:1 on white. |
| `SURFACE` | `#F5F7FA` | Conflict-row background, content-view header (already used in help CSS). |
| `SURFACE_HEADER` | `#EEF1F5` | Preview section-header rows (already used in help CSS). |
| `BORDER` | `#C8C8C8` | 1px frames around conflict rows and the badge. |
| `SP_XS, SP_SM, SP_MD, SP_LG, SP_XL` | `4, 8, 16, 24, 32` | Spacing scale, below. |
| `PRIMARY_BUTTON_QSS` | see below | Used by Generate Tables (main window) and Install Part (dialog). |

`PRIMARY_BUTTON_QSS` (exact):

```
QPushButton { background-color: #0078D4; color: white; padding: 8px 16px; font-weight: bold; min-height: 12px; }
QPushButton:disabled { background-color: #E1E1E1; color: #595959; }
```

Vertical padding is `8px` (a multiple of 4; the earlier `6px` was not) and `min-height` is the 12px content box, so the button is 8 + 12 + 8 = 28px high, matching the 28px minimum control height in Layout rules.

**Effect on the existing Generate Tables button (explicit):** `main_window.py` `_build_ui` currently styles Generate with `padding: 6px 16px` and `min-height: 20px` (32px total, no `:disabled` rule). Replacing that inline string with `PRIMARY_BUTTON_QSS` changes Generate in three ways: vertical padding 6px to 8px, total height 32px to 28px, and a new `:disabled` look. This is intended, so Generate and Install are identical in size and style. The existing Generate button has no `:disabled` rule, so it keeps its blue fill while `_set_scan_running(True)` disables it and looks clickable; the shared string fixes that. Install must never look enabled while it is disabled, so the `:disabled` rule is mandatory for both.

## Spacing Scale

Declared values (multiples of 4), as constants in `theme.py`:

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Gap between a field and its `↺` button; gap between a label and its hint line; badge inner padding. |
| sm | 8px | Default `setSpacing` for every layout in the dialog; form row spacing; gap between the three conflict toggle buttons; splitter handle width. |
| md | 16px | Dialog `setContentsMargins` (all four sides); gap between left-pane sections (use `addSpacing(SP_MD)`); button padding horizontal. |
| lg | 24px | Start-step vertical rhythm between heading, Downloads offer and Browse row; result-view gap between sections. |
| xl | 32px | Not used inside the dialog. Reserved for the start-step top inset. |
| 2xl / 3xl | 48px / 64px | Not used (desktop dialog). |

Layout rules:

- Dialog: `setContentsMargins(16, 16, 16, 16)`, `setSpacing(8)`. Default size 1100x720, minimum 900x600, centered over the main window. Size is not persisted (**default**).
- Splitter initial sizes `[440, 660]`, left pane minimum width 380, right pane minimum width 400. Ratio is not persisted.
- Left pane and preview pane content margins 0 (the dialog margin already provides the inset), spacing 8.
- Interactive controls (line edits, combos, buttons, conflict toggle buttons) have a minimum height of 28px.
- `↺` buttons are 24x24.
- Install progress bar: fixed height 16, width 240.

Exceptions: 1px and 2px borders (including the 2px `fieldFrame` border) and 4px accent bars on conflict rows are outlines, not spacing. No layout margin, layout spacing or padding value in Phase 5 is below 4 or off the 4-multiple scale; `fieldFrame` layout margins are 0. The main-window toolbar button keeps Qt's default toolbar spacing (the existing toolbar row has no declared scale); only new Phase 5 layouts must follow the table.

## Typography

Sizes are declared in points so they scale with system DPI. The Phase 2 review flagged mixed px/pt; new code uses pt only, and the two existing `font-size: 13px` tree labels move to the Heading size when `library_table.py` is touched.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (labels, fields, tree rows, buttons, hints) | 9pt (system default; do not call `setPointSize`) | Regular 400 | Native single-line metrics; 1.5 for wrapped rich-text blocks (blocking-reason strip, hints, notices) |
| Heading (left-pane section titles, preview section header rows, package header, start-step prompt) | 10pt | Bold 700 | 1.2 |
| Display (result-view banner "Installed ...", failure banner title) | 12pt | Bold 700 | 1.2 |
| Mono (diff and content view, rename-name preview, STEP hashes, `<Lib>:<FP>`, `${CUSTOM_3DMODEL_DIR}/...` values) | 9pt `Consolas` | Regular 400 | 1.2 |

Exactly three sizes (9, 10, 12 pt; Mono shares 9pt) and two weights (400, 700). Qt has no semibold at the default style, so bold is the second weight (matches the whole app today). Hints and secondary text use Body size in `MUTED` color, never a fourth size.

## Color

Qt terms: the 60/30 surfaces come from the platform palette (do not hard-code them); the explicit hex values below are the semantic colors.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `QPalette.Window` / `QPalette.Base` (`#F0F0F0` window, `#FFFFFF` trees and text boxes on Windows 11) | Dialog background, tree and list bases, line edits |
| Secondary (30%) | `QPalette.AlternateBase`, `SURFACE #F5F7FA`, `SURFACE_HEADER #EEF1F5`, `BORDER #C8C8C8` | Alternate tree rows, conflict-row background and frame, preview section-header rows, content-view header strip |
| Accent (10%) | `#0078D4` | See reserved-for list |
| Destructive | `#CC0000` | Overwrite action only, plus `ERROR`-severity text (see below) |

Accent reserved for (exhaustive):

1. The primary button fill (`PRIMARY_BUTTON_QSS`), used by exactly two buttons: **Install Part** in the dialog and the existing **Generate Tables** in the main window.
2. The install `QProgressBar` chunk.
3. The checked fill of the **Rename** and **Skip** toggle buttons in a conflict row (white bold text on `#0078D4`, about 4.5:1).

Everything else uses the system highlight for selection and focus. Links in the blocking-reason strip use `LINK #0057A0`, not the accent. Because the import dialog is window-modal, only one of the two primary buttons is ever interactive at a time.

Destructive `#CC0000` reserved for: the checked **Overwrite** toggle (red fill, white bold text) and its hint line; the failure banner when an install is rolled back; `Severity.ERROR` text and the `✖` glyph. Nothing else is red.

Semantic colors and where they apply:

| Meaning | Color | Elements |
|---------|-------|----------|
| Needs attention / blocked | `AMBER #8A5200` | 2px border on a blocking field; low-confidence and placeholder tokens of the library name; unresolved conflict left bar and "Needs a choice" text; `Severity.WARNING` rows; "Updating..." label; warning lines in the result view |
| Success / new | `SUCCESS #007700` | `+` glyph; resolved conflict left bar; "existing" library badge text; result banner check; `Severity.SUCCESS` |
| Unchanged / secondary | `MUTED #595959` | `=` glyph, hints, ages, package vendor name, disabled-button text |
| Info | default text color | `Severity.INFO`, `~` modified glyph (bold) |

Color is never the only cue. Every colored state also carries a word or a glyph: `Needs a choice`, `⚠`, `✖`, `✓`, `+ ~ =`, "existing" / "new". Contrast: every text color above is at least 4.5:1 on its background (`AMBER` on `AMBER_TINT` about 5.9:1).

`LogPanel.COLORS["warning"]` changes from `#CC7700` to `AMBER`; `info`, `error`, `success` keep their current values (`#000000`, `#CC0000`, `#007700`).

## Layout and Structure

### Main-window changes

| Element | Contract |
|---------|----------|
| File menu | New first item **`&Import Part...`**, `Ctrl+I`, status tip "Import a vendor package (.zip or folder) into Custom/". Followed by a separator, then the existing Generate / Restore / Rescan / Set KiCad Path items. **(default: shortcut and placement)** |
| Toolbar button | A plain `QPushButton` "Import Part..." as the first widget of the toolbar row, before Select All, with `addSpacing(16)` after it. Tooltip "Import a vendor package (Ctrl+I)". Not styled with the accent. **(default)** |
| Busy state | `_set_scan_running(running)` also toggles the Import action, the Import button, the Select All and Deselect All buttons (Phase 2 review fix) and drop acceptance. |
| Dialog open | While the import dialog is open, every other main-window control is unreachable because the dialog is window-modal (D-19). |
| Drag and drop | `setAcceptDrops(True)`. Behaviour table below. |
| Library trees (fold-in) | Symbols tree columns: Library Name 240 interactive, Source 100 interactive, Linked Footprints `Stretch`, Status `ResizeToContents` so Status is visible at the default size. Footprints tree: Library Name 240, Source 100, Status `ResizeToContents`. Status text also set as tooltip on the Status cell. `populate()` wraps `_updating` in try/finally. |
| Help dialog | Add: "Import Part..." and the import flow (start step, items, target library, fields, conflicts, install, result), the `Collision` status, `Ctrl+Shift+R`, `Ctrl+I`, and the add-only table behaviour after importing into a new library. Use `AMBER` in the help span. |

Drag-and-drop behaviour:

| Situation | Result |
|-----------|--------|
| `dragEnterEvent`, scan running or dialog open | Ignore the event (forbidden cursor) and `statusBar().showMessage("Import is unavailable while a scan is running.", 3000)`. |
| `dragEnterEvent`, idle, event has URLs | Accept (so `dropEvent` can explain a refusal). |
| `dropEvent`, exactly one local path that is a `.zip` file (case-insensitive) or a directory | Open the import dialog with that package loaded (skips the start step). |
| `dropEvent`, several paths | Refuse. Log warning: `Drop ignored: drop one .zip file or one folder at a time.` |
| `dropEvent`, one path that is neither a zip nor a folder | Refuse. Log warning: `Drop ignored: '{name}' is not a .zip file or a folder.` |

#### Package header row

`QLabel` with the package file name in bold, the detected vendor in `MUTED` ("Ultra Librarian", "Unknown vendor" for the generic adapter), and a **Change...** button right-aligned. Below it a 1px `QFrame.HLine`. Change... returns to the Start page and discards edits and conflict choices without a confirmation (nothing has been written; **default**).

#### Items (D-04, INTK-07)

| Item | 0 found | 1 found | Several found |
|------|---------|---------|---------------|
| Symbol | Not reachable (a package with no symbol is refused on the Start page, D-05) | Plain `QLabel` with the name | `QComboBox`, exactly one chosen, first preselected. A note "extends parent `{name}` is included automatically" appears under the combo when the chosen symbol has a parent. |
| Footprints | Label `No footprint in this package` in `AMBER` | Plain `QLabel` with the name | `QListWidget` with a check box per row, all checked by default, up to 6 rows visible then a vertical scrollbar. Unchecking the linked row moves "linked" to the first remaining checked row. Unchecking the last checked row is allowed and adds the blocking reason `Select at least one footprint`. |

Any change rebuilds the plan immediately (no debounce). The UI never passes a blank choice to `InstallOptions` (Phase 4 IN-04): when a section has one item, the value is that item.

#### Target library (D-11)

- Editable `QComboBox`, pre-filled with `LibrarySuggestion.name`. Dropdown order: the ranked `alternatives` first, a separator, then every existing `Custom/` library from `layout.list_existing_libraries` (read fresh each time the dialog opens). Typing rebuilds after the 300 ms debounce; picking from the list rebuilds immediately.
- To the right of the combo, a **badge** `QLabel` with a 1px `BORDER` frame, 4px vertical and 8px horizontal padding: `existing` in `SUCCESS`, or `new - creates .kicad_sym + .pretty` in default text, bold. Badge text follows the typed name against the fresh library list.
- Under the combo, a rich-text **token line** in Mono 9pt showing the name split on `_`. Placeholder tokens (from `placeholder_tokens`) and, while the text still equals the suggestion, low-confidence tokens (`TokenChoice.confident` false) are bold `AMBER`. A one-line `MUTED` hint appears when any token is amber: `Amber parts are guesses or placeholders. Pick an existing library or type a real name.` Once the user edits the text, only placeholders stay amber (an edit counts as confirmation of the rest). **(default)**
- A name that is empty, has a case-twin, or fails `sanitize_name` shows the Issue text from the plan in the preview and a blocking reason.

#### Footprint (D-14, PREV-02)

- `Name` `QLineEdit` pre-filled with the sanitised vendor footprint name, with a `↺` button.
- When the vendor name and the sanitised name differ, a `MUTED` hint reads `Vendor name: {original}`.
- The linked footprint changing resets this field to that footprint's default name (D-14b).

#### Fields (D-13, D-14, PREV-03, PREV-04)

Rows in this order. The first two are read-only.

| Row | Control | Behaviour |
|-----|---------|-----------|
| Symbol | `QLabel` | `{sanitised}`, or `{vendor} → {sanitised}` when they differ (LIB-03). Changes only through a conflict's Rename. |
| Footprint field | Read-only `QLineEdit`, Mono, selectable | Shows `<Lib>:<FP>` **read from the rebuilt plan, never computed in the widget** (D-14, PREV-03). Shows `(none)` in `MUTED` when `plan.linked_footprint` is None. |
| Value | `QLineEdit` + `↺` | Pre-filled with what the plan would write. Cannot be emptied (blocking). |
| Datasheet | `QLineEdit` + `↺` | Emptying installs an empty value. Placeholder text `Empty - the field will be written blank`. |
| Description | `QLineEdit` + `↺` | Same as Datasheet. Single line; long text scrolls inside the box. |
| Manufacturer | `QLineEdit` + `↺` | Pre-filled per D-11 default. Same clear semantics as Datasheet. |
| MPN | `QLineEdit` + `↺` | Cannot be emptied (blocking); tooltip `MPN names the 3D model file`. |

`↺` is disabled when the field already equals its default; tooltip `Restore default: {value}`. Picking a different symbol reloads every field from the new symbol's defaults (D-14b); changing only the target library keeps all edits.

#### Amber blocked-field highlight (D-09)

Do not restyle `QLineEdit` or `QComboBox` directly: a border stylesheet on those widgets drops the native drop-down arrow and look. Wrap each blockable control in a `QFrame` with `objectName="fieldFrame"`, layout contents margins 0 (the frame's own 2px border already insets the child, so no spacing value is needed), and set the dynamic property `blocked` (re-polish after changing it):

```
QFrame#fieldFrame { border: 2px solid transparent; border-radius: 2px; }
QFrame#fieldFrame[blocked="true"] { border: 2px solid #8A5200; }
```

The frame reserves its 2px border at all times (transparent when not blocked), so the layout does not shift when the highlight appears. Blockable controls: library combo, Footprint name, Value, MPN, each rename field, and the footprint list.

#### Conflicts (D-12, D-14a, PREV-05)

One `QFrame` row per `Conflict`, `SURFACE` background, 1px `BORDER`, plus a 4px left bar: `AMBER` while unresolved, `SUCCESS` once a choice is made. Internal margins 8, spacing 4.

```
| footprint DQK0006B exists in IC_MOSFET_TI.pretty     Needs a choice |
| [Overwrite] [Rename] [Skip]            (rename field when Rename on) |
| Skip - keep the existing footprint and link it                       |
```

- Line 1: kind in bold (`symbol`, `footprint`, `3D model`), the item name, `exists in`, and where it lives (`Conflict.existing`). The text elides in the middle with the full text as tooltip. At the right end, `Needs a choice` in `AMBER` bold (hidden once resolved).
- Line 2: three checkable `QPushButton`s **Overwrite**, **Rename**, **Skip**, none checked at first, 8px apart. Clicking the checked button again does nothing. Checked styling: Overwrite = `#CC0000` fill, white bold text; Rename and Skip = accent fill, white bold text. Choosing **Rename** reveals a `QLineEdit` to the right of the buttons (min width 160) pre-filled with `Conflict.suggested_name` (editable; editing rebuilds after the debounce).
- Line 3: the one-line hint in `MUTED` (the Overwrite hint is `ERROR` color). Hint copy is in the Copywriting section.
- Double-click anywhere on the row opens the content view (existing vs incoming, D-08). The row is also focusable and `Enter` / `Space` on the focused row opens it.
- Choices are keyed by `Conflict.key` and survive rebuilds while the key is still in the new plan (D-14a). A key that disappears drops its choice; a new key starts unresolved. There is no "Overwrite all", "Skip all" or any bulk control.
- Several conflicts stack vertically with 8px between rows and the left pane scrolls.

#### Preview (D-06, D-07, PREV-01, PREV-06, PREV-07)

Right pane = a Heading label `Preview`, a 4px-high `QProgressBar` strip (hidden unless busy), and one `QTreeWidget` with two columns **Item** (stretch, elide in the middle) and **Detail** (resize to contents). `setAlternatingRowColors(True)`, `setWordWrap(True)`, no horizontal scrollbar, all item text selectable via copy (`Ctrl+C` copies the current row text).

Section header rows: Heading font, `SURFACE_HEADER` background, text `{Name} ({count})`. Empty sections are not shown except **Files**. Order is fixed:

| Section | Row content |
|---------|-------------|
| **Files** | Item: glyph + repo-relative path (`+` new in `SUCCESS` bold, `~` modified in default bold, `=` unchanged in `MUTED`). Detail: the words `new`, `modified`, `unchanged`, plus the size for a STEP/binary file. |
| **Renames** | Item: `{old} → {new}`. Detail: kind (`symbol`, `footprint`, `model file`). Includes sanitised-name renames (LIB-03). |
| **Path rewrites** | Item: field name (`Footprint`, `Model`, `ki_fp_filters`). Detail (Mono): `{old} → {new}`, with `(none)` for an absent old value. Values come from the plan, so `<Lib>:<FP>` and `${CUSTOM_3DMODEL_DIR}/<MPN>.<ext>` here always equal what is written. |
| **Format** | Row 1: `Symbol format {source_version} → {target_version}`. Row 2, the kicad-cli action, one of: `kicad-cli will normalise the incoming symbol` (default color), `Already in the target format` (default), `kicad-cli not found - symbol merged as-is` (`⚠`, `AMBER`), `Incoming file is newer than the library - refused` (`✖`, `ERROR`). |

| **Issues** | One row per `Issue`, glyph + text, colored by `Severity` (`✖` ERROR, `⚠` WARNING, plain INFO), including `No 3D model found` (INTK-08), pin/pad mismatch and name-elsewhere warnings when the plan carries them. |

Rebuild rendering rules (D-06, D-07):

- The tree is re-rendered per rebuild result; section expand state (keyed by section name; new sections default expanded) and the vertical scroll value are restored. Changed rows are **not** flashed or highlighted.
- While a rebuild is pending or running, the previous tree stays visible, an `Updating...` label in `AMBER` appears next to the `Preview` title, the busy strip appears only if the rebuild takes longer than 150 ms (**default**, avoids flicker), and **Install is disabled immediately** with the blocking reason `Updating preview...`. A result from a superseded rebuild (generation counter) is discarded without touching the tree.
- First build after opening a package: the Edit page shows a centered `Building preview...` label with an indeterminate bar instead of the empty tree.

#### Content view (D-08)

Secondary `QDialog`, window-modal to the import dialog, 800x560, minimum 600x400, title `{repo-relative path} - new file | changes | existing vs incoming`. A header strip (`SURFACE`) with the path, then a read-only `QPlainTextEdit` (Mono, `NoWrap`), then a Close button (Esc also closes).

| Content | Rendering |
|---------|-----------|
| New text file | The planned text, no coloring. |
| Modified text file (`.kicad_sym`, `.kicad_mod`) | `difflib.unified_diff` of current file vs planned bytes, 3 lines of context. Line-level coloring by `QSyntaxHighlighter`: `+` lines on `SUCCESS_TINT`, `-` lines on `ERROR_TINT`, `@@` lines bold `MUTED`. The `+` / `-` characters stay visible, so color is not the only cue. |
| Conflict row or conflict preview row | Same unified diff, existing item (`-`) against incoming (`+`). |
| STEP / binary file | Text block: `{name}`, `Size: {n} KiB`, `SHA-256: {hex}`; for a modified binary both the existing and the planned hash. |
| Unchanged file | `This file is unchanged by the install.` |
| Large diff | Cap at 5000 lines or 512 KiB, whichever comes first; the last line reads `Diff truncated: showing the first {n} of {total} lines.` |

#### Bottom row (D-09, D-10)

A horizontal row, 8px spacing, 28px high controls: left, the **blocking-reason strip**; right, the **Install** button (`PRIMARY_BUTTON_QSS`, label `Install Part`, min width 112). Install is **not** the dialog's default button (`setAutoDefault(False)` and `setDefault(False)` on every button), because Enter inside a line edit must never trigger an install. `Ctrl+Return` (a `QShortcut` on the dialog) triggers Install only when it is enabled.

Blocking-reason strip:

- A rich-text `QLabel` (`setWordWrap(True)`, max 3 lines then elided, full list in the tooltip). When blocked, `AMBER_TINT` background, 8px padding, leading `⚠ Install is blocked:`, then the reasons separated by ` · `, each a link in `LINK` underlined. `linkActivated` focuses and scrolls to the matching control (field, library combo, footprint list, or conflict row) and flashes nothing.
- When not blocked and the plan has changes: `✓ Ready to install: {n} new, {m} modified, {k} unchanged files` in `SUCCESS`.
- When the plan `is_noop`: `Nothing to install: this part is already in {Lib}.` in `MUTED`, Install disabled (**default**).
- While rebuilding: the single reason `Updating preview...` replaces all others (the others could be stale).
- Reason order: Updating, package/plan ERROR issues, library name (empty or placeholder), Value/MPN empty, footprint selection, unresolved conflicts (one reason each, in row order), empty rename names.

#### Install in progress (D-10)

- Click Install: a banner (if any) is dismissed, the left pane is disabled, the Package row and Change... are disabled, the strip is replaced by `{step text}` (Body, `MUTED`) plus a determinate `QProgressBar` (240x16, accent chunk, `setRange(0, 100)` from the `progress(message, current, total)` callback), and the button reads `Installing...` and is disabled. The preview tree stays scrollable and double-clickable (read-only).
- No Cancel button. `closeEvent`, `reject()` and Esc are ignored until the worker finishes; the status bar of the main window is not used.
- A progress callback that stops arriving does not stall the bar: it holds its last value and shows the last step text.

#### Result view (D-15, D-16, D-18, POST-01/02/05)

On failure the dialog returns to the Edit page. The banner stays until dismissed, the next Install click, or a successful install. Because files on disk may have changed, the plan is rebuilt automatically after a failure so a retry cannot hit the stale-plan guard.

Main-window effects when the result view appears (D-16, D-17, D-18, no dialog needed): the scan starts through `_start_scan`; afterwards the new library's symbol and footprint rows are checked, expanded, scrolled into view and made current in both trees without touching the rest of the selection; `statusBar().showMessage("Installed {Symbol} into {Lib}", 5000)`; all result Issues also go to the log panel by severity.

#### Start page and refusals (D-02, D-05)

A centered column (max width 560, top inset 32, 24px between blocks):

1. Heading (10pt bold): `Choose a part package`.
2. Body: `Open a .zip from Ultra Librarian, SnapEDA or SamacSys, or a folder of KiCad files. Nothing is written until you click Install Part.`

If the Downloads folder cannot be found: `Downloads folder not found.` The offer is shown whatever the zip's age; the age text is the only signal (**default**; no stale cutoff).
