<objective>
POST-02 and the rest of D-16. When an install creates a library, its entries are added to the library tables in the current destination. Nothing else in those files changes, and the main tree's ungenerated selection is never written. When an existing library got the part but is not in the tables, the user is told to press Generate. In both cases the installed library is brought into view in both trees.

Purpose: CONTEXT.md D-17 requires "every other entry stays exactly as it is on disk". RESEARCH Pattern 6 shows `write_tables` cannot do that: it regenerates every managed entry, drops flags and removes stale entries. So this plan adds a small add-only helper (RESEARCH open question 3, Option B; CONTEXT.md lists this under Claude's Discretion) and wires it into the post-install step from plan 05-01.
Output: `table_generator.add_library_entries`, `MainWindow._finish_post_install`, and tests.
</objective>
