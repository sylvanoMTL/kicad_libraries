<objective>
Close review finding CR-02 (UAT item 2 in 03-UAT.md). Today `open_package` promises that expected failures "come back as ERROR Issues, never raised", but two things break that promise. First, a corrupt LZMA member raises `lzma.LZMAError` out of the function, because `_copy_member` does not catch it; on Python 3.14 a corrupt zstd member raises `compression.zstd.ZstdError` the same way. Second, `tempfile.TemporaryDirectory(...)` and `staging.resolve()` run outside any try block. After this plan every decompressor fault becomes ERROR `intake.corrupt`. The staging folder, including any files already staged, is then removed through `_refuse` before the function returns. A temp folder that cannot be created becomes ERROR `intake.staging_failed`.

Purpose: INTK-06 (zips are read safely) and INTK-01 (a package opens or is refused with a reason). This keeps the Phase 1 D-07 Issue contract for the call the Phase 5 GUI worker will make on user downloads. It closes the CR-02 gap recorded against the reopened T-03-09 in 03-SECURITY.md.

## Decisions in this plan

- **WR-03 is not folded in; it stays open.** WR-03 is "a staging write failure reported as a corrupt archive". CR-02's own failure modes are reported honestly without it:
  - A decompressor fault (LZMA, zstd, or any codec) is a genuine read fault of the vendor archive, so `intake.corrupt` with "Could not read member ..." is accurate.
  - A temp folder that cannot be created or resolved is caught before any member is opened, and it gets its own new code `intake.staging_failed`.

  The remaining misattribution is an `OSError` from opening or writing the staged copy inside `_copy_member`. CR-02 neither introduces nor changes it, and none of its new paths depends on it. So the write-side reporting is left exactly as it is, and WR-03 keeps its own fix and its own code later.
- **No last-resort catch-all.** The review suggested an optional catch-all around `_stage_zip`. It is declined, because the project convention keeps broad catches at the thread boundary only (`ScanWorker.run`, later the Phase 5 worker). Instead, every decompressor error class this interpreter can raise is listed in `_READ_ERRORS`. A tripwire test compares the codecs `zipfile` can write with the codecs the corrupt-member test covers, so a codec added by a future Python fails a test instead of escaping silently.
- **Guarded imports.** `_READ_ERRORS` is built from guarded imports, the way `zipfile` handles its optional modules. `lzma` can be missing on some Linux builds, and then `zipfile` raises `RuntimeError` for LZMA members, which is already caught. `compression.zstd` exists only from Python 3.14. So the module still imports on Python 3.10 to 3.13 and on builds without lzma.
