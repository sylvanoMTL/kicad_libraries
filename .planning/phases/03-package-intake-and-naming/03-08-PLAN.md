## Decisions in this plan (planner, from measurements on this machine)

Measured with the project venv (Python 3.14.4) during planning:
- The parser builds one `Node` plus one `list` per token (list, atom or string), about 200 bytes of heap per node. Dense balanced text such as `(a)` repeated costs 1.1 s and 142 MiB per MiB of input; 4 MiB took 6.3 s and peaked at 570 MiB.
- A seeded random mix of `(a)`, `(b 1)`, `()`, `(c d)`, `(e (f))` of 3.6 MiB deflates 10.8:1 (well inside the 200:1 rule), holds 1.82 million nodes and parses in 3.3 s. This is the CR-01 reproduction class. In a folder there is no ratio rule at all, so at the old 100 MB cap one file costs on the order of 10 GiB and minutes.
- Real files: the largest file in `Custom/` is 48 KiB (about 2,000 lists). The UL sample symbol is 18 KiB. KiCad's own 9.71 MiB `MCU_ST_STM32U5.kicad_sym` (a whole multi-part library) has 1.17 million nodes, about 120,000 per MiB. KiCad's 6.06 MiB demo footprint `BGA96C80P9X16_750X1350X120.kicad_mod` is large only because of an embedded 3D model, and it has 81,662 nodes and parses in 0.15 s.

Choices, which the verifier's "about 8 MB" example does not settle alone:
- A byte cap of 8 MiB on its own still lets a dense hostile file just under the cap cost about 1.1 GiB and 13 s. So this plan adds the parser node ceiling the review proposed as optional (CR-01 "Fix", second paragraph).
- `MAX_KICAD_TEXT_NODES = 1_000_000` bounds any file at about 200 MiB and under about 2 s. That is more than 10 times any single-part vendor file, and it admits real-density KiCad text up to the byte cap (8 MiB x 120,000 per MiB is about 0.96 million).
- `MAX_KICAD_TEXT_BYTES = 8 * 1024 * 1024` bounds the read and decode, and it still admits the 6.06 MiB embedded-model footprint above.
- Both are module constants beside the D-06 caps in `importer/package.py`, because D-06 keeps caps "as module constants in one place". Configurable limits were declined in 03-CONTEXT.md, so neither cap is a setting.
- Skipping, not refusing: the gap truth says the file is "skipped with a WARNING", so an over-cap file goes through the existing `intake.unreadable_file` WARNING path in `locate`. It never becomes a whole-package refusal.
