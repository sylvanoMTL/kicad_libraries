Close verification gap 1 (review CR-01) and review warning WR-01 in `kicad_lib_manager/importer/applier.py`.

Gap 1: `apply_plan` only rolls back when a write or verify returns an `Issue`. An exception from the write loop, the `progress` callback, `_make_folders` (`folder.resolve()` sits outside its `try`) or `verify.verify_install` escapes after files were written, and `_rollback` never runs. The verifier reproduced it: a raising progress callback and a raising `verify_install` both leave `3DModels/X.stp` and `FP.kicad_mod` on disk.

WR-01: the backup stamp is local time and pruning ranks folders by name, so after a clock step-back with ten or more later-named folders, `prune_install_backups` deletes the folder the running install just made. That folder is the rollback safety net that gap 1 and gap 2 rely on.

Purpose: INST-07 ("if any write fails, every file touched by the install is restored") and the phase goal ("transactionally", "failures are rolled back") must hold for every failure, not only failures that arrive as `Issue` values. This keeps the importer convention: return `Issue` values with stable codes and never raise to callers, except that an interrupt (KeyboardInterrupt, SystemExit) propagates after the rollback.
Output: exception-safe `apply_plan`, guarded progress callback, `prune_install_backups(..., exclude=)` with a UTC stamp, and their regression tests.

Gap closure scope: this plan does not touch plans 04-01 to 04-10 or their SUMMARY files. Plan 04-13 builds on the transaction holder this plan adds (gap 2, CR-02) and records the review dispositions.
