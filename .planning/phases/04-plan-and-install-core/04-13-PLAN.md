<objective>
Close verification gap 2 (review CR-02), the stale-plan check that is not held across the kicad-cli gate window, and record the review dispositions for everything the gap plans fixed.

`_preflight` hashes every target. Then `_gate` runs up to three kicad-cli processes (60 s timeout each) before the backup and the first write, and nothing re-checks the hashes afterwards. The verifier reproduced it: a runner that rewrites the `.kicad_sym` during the gate yields `ok=True` with `install.done`, and the live file loses the edit. The edit survives only in a backup folder that the result never mentions. The rollback would also restore the stale preflight pre-image instead of what was backed up.

Purpose: INST-07 and the phase goal ("transactionally") require that a newer file is never silently overwritten. The 04-07 stale-plan guarantee must hold from the preflight to the last write, not only up to the gate. LIB-02 creates new library files, so a path that appears during the install must not be clobbered either.
Output:
- a post-gate freshness pass with the backup copy as the authority and as the rollback pre-image;
- a re-check immediately before every write;
- an `on_call` hook in FakeCli;
- the regression tests;
- the disposition record for CR-01, CR-02, WR-01, WR-03 and WR-05.

This plan depends on 04-11 because it extends 04-11's `_Transaction` holder and `_transaction` function in the same file, and its rollback path. It depends on 04-12 because the disposition record names 04-12 as the fix for WR-03 and WR-05, and the full suite must pass on the combined tree. Plans 04-01 to 04-10 and their SUMMARY files stay untouched.
</objective>
