<objective>
Finish the commit panel. The tracer panel from plan 06-01 handles only the happy path. Here it becomes the full state machine of D-01 to D-20. It shows every probe state (probing, unavailable, refused, offer to switch, ready); the D-09 amber files, the D-10 count and the D-13 earlier commits; the parent checkbox with its reason; the live read-only parent message (D-19); the locks while committing (D-07); and the done, failed and not-committed outcomes (D-03, D-04, D-06). The widget never runs git. It only renders values and emits commit_requested, switch_requested and file_activated.

Purpose: success criterion 1 (the branch or detached state, the exact files and the editable message are visible before confirming) and the switch offer of success criterion 3.
Output: `widgets/commit_panel.py` and `tests/test_commit_panel.py`.

Phase 6 has no UI-SPEC of its own. The visual and copy rules come from the Phase 5 UI-SPEC: plain-text labels, `theme.py` colours (AMBER for attention, AMBER_TINT strips, ERROR, SUCCESS, MUTED), Body 9pt, Heading 10pt bold, Mono Consolas 9pt, 4/8/16/24 spacing, 28 px controls, glyphs ⚠ ✖ ✓, colour never the only cue, and accent fill reserved for Install Part and Generate Tables (so Commit is a plain button).

## Decisions recorded in this plan

- Only amber (dirty) rows open a view on double-click. A clean row has nothing to compare, because its pre-import content equals HEAD.
- An outcome with nothing committed returns to "ready". A click after fixing the cause is the user's decision, not an automatic retry (D-06). An outcome with a Custom commit is terminal (D-03: no Retry).
- The earlier-commit list is capped at 10 lines in the panel. The parent message itself lists every commit.
- Commit is a plain button. The Phase 5 UI-SPEC reserves the accent fill for Install Part and Generate Tables.
