## Decisions recorded in this plan

- Two Qt-free importer modules: `commit_plan.py` is pure (no git), so plan 06-04 can test the message and file rules without git. `commit_step.py` does the orchestration. `gitops.py` imports only `models`, so a top-level module never imports the importer.
- The commit plan is built on the GUI thread (it only hashes the planned bytes). All git work runs on TaskWorkers.
- Only one git worker exists at a time (`_git_worker`). The probe also blocks Close, which costs a fraction of a second and keeps one rule for every git job.
- The parent message is built inside the commit job after the Custom commit exists. The panel only ever shows `parent_preview` with the `<new commit>` placeholder (RESEARCH Pattern 5 correction of D-18).
- Phase 6 Issue codes start with `commit.` or `git.`, so Phase 5 tests that filter on `import.` keep their meaning.
- Flagged costly (Task 1): the dataclass and panel contracts fixed here.
