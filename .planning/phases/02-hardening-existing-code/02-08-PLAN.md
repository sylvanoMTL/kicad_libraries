Phase 1 fsutil (kicad_lib_manager/fsutil.py), the functions this plan extends:
```python
def atomic_write_bytes(path, data, *, retry_delays=_RETRY_DELAYS, sleep=time.sleep) -> Issue | None   # fs.read_only / fs.locked / fs.write_failed
def atomic_write_text(path, text, *, bom=False, retry_delays=..., sleep=...) -> Issue | None           # encodes, then atomic_write_bytes; raises UnicodeEncodeError today
def backup_file(path: Path, backup_dir: Path) -> Path | Issue      # "<name>_backup_<N>" with N = max+1, exclusive create, shutil.copystat, fs.backup_failed
def decode_source(data: bytes, name: str) -> SourceText | Issue    # counts crlf / lf / cr; mixed = (crlf and lf) or cr; one fs.mixed_eol WARNING whose text always says "(CRLF and LF)"
```
`atomic_write_bytes` checks `os.access(path, os.W_OK)` once before the temp write (fs.read_only), then retries `os.replace` on `PermissionError` and finally returns fs.locked "Could not write {name}: file is in use" (asserted verbatim by tests/test_fsutil.py around line 84; that lock test must keep passing). `fsutil` imports `os`, `re`, `shutil`, `sys`, `time`, `uuid` and `from .models import Issue, Severity`; `stat` is not imported yet. The read side already uses the code `fs.bad_encoding` for invalid UTF-8 input.

tests/test_fsutil.py line ~203: `test_backup_file_name_matches_backup_existing_with_gaps` does `from kicad_lib_manager.table_generator import backup_existing`. Plan 02-01 (same wave) keeps `backup_existing`; plan 02-03 deletes it once no test imports it.
