<objective>
Close UAT gap G-07-5. An unusable 3D model source is an ERROR, shown in red, that blocks Install Part until the user removes it or adds a usable model.

User decisions (07-UAT.md G-07-5 `decisions:`, 2026-10-24, binding):
- An unusable model source shows a red (theme.ERROR) plain-text error note and blocks Install through a blocking Reason that targets the model row.
- Read failures (the model worker fails) block too.
- A zip that holds any unusable model file is rejected as a whole; nothing from it is attached.
- A Remove button clears a rejected source only. Detaching a successfully attached model is out of scope. Add 3D model... remains the way to add another source.
- INFO duplicates stay non-blocking.
- This supersedes the 07-08 must-have "Refused/empty source leaves candidate and row unchanged; reason as plain-text amber note". Task 3 rewords it.

Root cause (.planning/debug/unusable-model-source-not-blocking.md): this is a design gap, not a regression. Plan 07-08 specified that a refused model source is closed and forgotten. It never reaches the candidate, FormStatus or blocking_reasons, so it cannot block Install. The core already returns Severity.ERROR intake.no_model_in_source, but the dialog hard-codes the amber tone in _on_model_attached and _on_model_failed. The greyed-out Install in UAT test 5 came from an unrelated unresolved symbol conflict (the part was already installed in live Custom/ during test 3), not from the refusal.

Design choices (Claude's discretion, recorded here):
- The dialog keeps only the rejected source's file name and its first ERROR Issue (`RejectedModel`). The rejected package is still closed at once, so a rejection holds no file handle or staging folder.
- The reason text is `Error: <first ERROR text>`, the same prefix as plan errors, placed right after the build-failure or plan-error block in blocking_reasons.
- The "model" reason target is the Remove button, the control that fixes the reason. No amber field frame is added for the model row, so theme.py does not change: theme.ERROR already exists and is already imported by import_dialog.py.
- A duplicate result while a rejection is held keeps the rejection, because a duplicate attaches nothing. Only a successful attach, Remove, Change..., a new open or close clear it.
- The partly-bad case gets its own ERROR code, intake.unusable_model_in_source. The all-bad case keeps intake.no_model_in_source and its text, which the user saw in UAT and which existing tests pin.

Purpose: UAT test 5 passes. A bad model file can no longer be overlooked before Install, and the user can recover from it in place.

Output: the form rule, the attach rule, the dialog state, Remove and the red note, help text, superseded-doc rewording, and tests for each.
</objective>
