<objective>
Close UAT gap G-07-8. The clickable reasons in the Import dialog's status strip carry a tooltip that says they jump to the control that fixes the reason.

User decision (planning context, 2026-10-24, binding): one strip-wide tooltip (the reason list plus a click hint), forced rich text, and a scoped strip stylesheet so the tooltip uses normal colours. Amend 05-UI-SPEC.md :353 and :517.

Root cause (.planning/debug/reason-link-no-tooltip.md): this is a spec gap carried into code. The blocked strip's only tooltip is the reason list (05-UI-SPEC E11/overflow), so with one reason it repeats the visible text and never says the reason is a link. _set_strip also applies a selector-less `background-color: AMBER_TINT` stylesheet, which Qt applies to the strip's QToolTip too, so the tooltip draws amber on amber and blends in. A side defect: a single escaped reason has no tag, so the tooltip shows as plain text and the entities appear literally.

Design choices (Claude's discretion, recorded here):
- The hint text is the public constant STRIP_LINK_HINT, so tests and later copy use one string. Its second sentence covers "plan" reasons, which focus the preview.
- The tooltip is "<p>" + escaped reasons joined by "<br>" + "</p><p><i>" + escaped hint + "</i></p>". The leading <p> makes Qt.mightBeRichText true for any reason count, which is the forced rich text the decision asks for.
- No per-link tooltip through linkHovered. The diagnosis rates it as more state for little gain on a strip of at most three lines, and the decision chose one strip-wide tooltip.
- This plan runs after 07-10 (same file, and its new "model" reason shows in the same strip), 07-13 (same file) and 07-11 (same UI-SPEC file).
- The test checks the stylesheet selector and does not sample tooltip pixels, because a pixel read is display and DPI dependent and flaky offscreen. The tooltip label Qt creates is named "qtooltip_label" (probe below), so a QLabel#installStrip rule cannot reach it.

Purpose: UAT test 8 passes. The owner can see that a blocking reason is a link before clicking it.

Output: the tooltip and stylesheet change, its tests, and the UI-SPEC amendment.
</objective>
