<objective>
Make the KiCad Library Manager start instantly by reusing the last scan, and let the owner rescan one library from the right-click menu.

Purpose: every start currently runs the full scan, which fully loads all ~6000 WurthElektronik `.kicad_mod` files for the 3D path check. Custom/ is small, so almost all of that time is spent re-reading files that did not change. A cheap stat check (no file parsing) decides at startup whether the saved scan still matches the disk. After editing one library in KiCad, the owner can refresh just that library without a full scan.

Output: a Qt-free `kicad_lib_manager/scan_cache.py`; a cache path helper in `settings.py`; startup reuse and cache refresh in `main_window.py`; `rescan_library` in `library_scanner.py` (plus `atomic_check.summary_line`); a "Rescan this library" context-menu entry in `widgets/library_table.py`; new and extended tests; and a CLAUDE.md GUI note.

Owner decisions (locked, from the brief; cited as O-NN in the tasks):
- O-01: On app start, show the last scan result instantly from a saved cache instead of running the full scan.
- O-02: Rescan automatically at startup only when a library file changed since the saved scan. The check is a cheap stat walk of the .kicad_sym / .kicad_mod / .pretty paths (mtime and size). WurthElektronik's files are covered by the same stat walk, so its submodule commit needs no separate check.
- O-03: The Rescan button and menu (`MainWindow._on_rescan`) always run a full scan and refresh the cache.
- O-04: A missing, corrupt, unreadable or older-format cache falls back to a full scan. It never crashes and never shows stale data silently, and it logs one plain line saying which case happened.
- O-05: The quiet post-install rescan (`_start_scan(show_progress=False)`) stays a full scan.
- O-06: The cache layer is Qt-free, registered in `tests/test_layering.py`, stdlib only, written atomically, and stored outside the repo and Custom/. Log lines are plain language with no internal field names.
- O-07: Right-clicking a library name in either tree offers "Rescan this library". It re-reads only that library's files, including the 3D path check for a footprint library and the atomic check and changed-part marks where they apply. It replaces that library's entries in the current ScanResult, then re-runs the nickname-collision and missing-footprint-link cross-checks on the merged result.
- O-08: The library rescan refreshes the trees keeping the current selection, updates the saved cache, and logs one plain line naming the library.
- O-09: The library rescan runs off the GUI thread and is refused while another scan runs (same guard as `_start_scan`).
- O-10 (planner's call, documented here): a library whose file was deleted or renamed since the last scan falls back to a full scan. A rename also creates a new library that only a full scan can find. A library that shares its nickname with another library also falls back, because its log lines cannot be told apart by name.

Claude's discretion, decided here:
- Cache location: `<folder of settings.ini>/scan_cache/<first 16 hex of sha256(normcase(resolved repo root))>.json`. On Windows that is `%APPDATA%/KiCadExtLibManager/scan_cache/`. Both GUI test files already redirect QSettings into tmp_path, so every existing test is isolated without edits. The main checkout and a worktree each get their own file.
- The freshness fingerprint has these parts:
  - mtime_ns and size of every `.kicad_sym` and `.kicad_mod` file, every file under `Custom/3DModels/`, and every `.gitignore` under `Custom/`;
  - the list of `.pretty` folders;
  - the Custom git HEAD, read from the `.git` files with no subprocess;
  - the resolved KiCad footprint folder, with its own mtime and the mtime of its sibling `3dmodels` folder;
  - a hash of the app's own `.py` files, so cached atomic verdicts never outlive a rule change.
  The cache stores the result with `selected` left out. Selection is always re-derived by the GUI.
- After a footprint library rescan, the Atomic_ symbol libraries whose Footprint links name that library are re-checked too, because their footprint and 3D model verdicts read that library's files.

Create `kicad_lib_manager/scan_cache.py` with a module docstring saying it is Qt-free and stdlib only (O-06). Imports: json, hashlib, os, functools, datetime, dataclasses, pathlib, plus `from . import fsutil`, `from .library_scanner import SKIP_DIRS, find_kicad_footprint_dir` and the model classes from `.models`. Define `FORMAT = 1`, `MAX_CACHE_BYTES = 64 * 1024 * 1024`, and the module constants `KIND_SYMBOL = "symbol"` and `KIND_FOOTPRINT = "footprint"` (Task 2 uses them).

Fingerprint (O-02):
- `fingerprint(repo_root, kicad_fp_dir) -> dict` is built from JSON types only: `{"files": {rel: [mtime_ns, size]}, "folders": [sorted rel], "custom_git": str | None, "kicad": [dir str or "", mtime_ns | None, mtime_ns | None], "complete": bool}`.
- Walk with an iterative os.scandir stack from repo_root. At the top level only, skip names in SKIP_DIRS, mirroring `_in_skip_dir`. Do not follow directory symlinks. Use `DirEntry.stat()`, which is cached on Windows; a stat walk of this repo measured about 0.4 to 0.7 s with os.stat, and scandir is cheaper.
- Record a directory in `folders` when its lowercased name ends with `.pretty`. Record a file in `files` when its lowercased name ends with `.kicad_sym` or `.kicad_mod`, when its rel path starts with `Custom/3DModels/`, or when it is named `.gitignore` under `Custom/`.
- rel paths are repo-relative posix strings. Any OSError during the walk sets `complete` False and the walk goes on.
- `kicad` uses the folder the scan would use: `kicad_fp_dir` if given, else `find_kicad_footprint_dir()`. Record its path string, its own st_mtime_ns and the st_mtime_ns of `<dir>.parent / "3dmodels"`, with None for a missing one.
- `custom_git` comes from a private `_custom_git_state(custom_dir) -> str | None`:
  - Return "none" when `Custom/.git` does not exist.
  - A `.git` folder is the git dir. A `.git` file must start with `gitdir:`; resolve a relative target against custom_dir.
  - Read `HEAD`. A detached HEAD returns its text. For `ref: <name>`, the name must start with `refs/` and contain no `..` part, else return None.
  - The ref value comes from the loose ref file in the git dir, then in the commondir (`<gitdir>/commondir` text, relative to the git dir). Failing that, use the matching line of `packed-refs` in the commondir, then in the git dir. If none is found, use "" (an unborn branch).
  - Return `HEAD text|ref value`. Any OSError or UnicodeDecodeError returns None, and None makes `complete` False.
  - The git index is deliberately left out, because the scan's own git status may rewrite it.

Serialisation:
- Write explicit encode and decode helpers per model type: FootprintRef, Issue (severity as its value), FixSpec, Violation (fixes and choices as lists, fill as an object or null), Finding, SymbolEntry, ChangedFootprint, SymbolLibrary, FootprintLibrary, ScanResult.
- Public entry points are `encode_result(result) -> dict` and `decode_result(data) -> ScanResult`.
- Never write `selected`. Decode it as False.
- Decode strictly: a wrong type, a missing key, an unknown Severity or a status other than None/"new"/"changed" raises ValueError, TypeError or KeyError. Decode tuples back to tuples.
- Use json only. Never pickle or eval.

Code signature: `_code_signature()`, cached once per process with functools.lru_cache. It is the sha256 over the sorted (posix relative path, bytes) of every `*.py` under `Path(__file__).parent`, skipping `__pycache__`. Return "" on OSError; load_fresh treats "" as a version mismatch.

Payload: `{"format", "code", "repo_root": normcase(str(repo_root.resolve())), "saved_at": local ISO time to the second, "fingerprint", "result"}`.

`save(cache_file, repo_root, kicad_fp_dir, fp, result, *, saved_at=None) -> Issue | None`:
- mkdir the parent folder, then write compact JSON with `fsutil.atomic_write_text`.
- On any failure return `Issue(Severity.WARNING, "cache.save_failed", "Could not save this scan for the next start: <reason>")`. The reason is the fsutil Issue text or the OSError text. A None fp gives the reason "the library files could not be listed".

Define `@dataclass CacheCheck` with fields `result: ScanResult | None`, `note: Issue` and `fingerprint: dict | None`. `load_fresh(cache_file, repo_root, kicad_fp_dir) -> CacheCheck` checks in this order. Every note is Severity.INFO, and these exact texts are what the tests assert (O-04):
1. File missing: code cache.missing, "No saved scan yet; scanning the whole repository."
2. Size over MAX_CACHE_BYTES, unreadable, invalid UTF-8 or JSON, not a dict, or a saved_at that does not parse: code cache.unreadable, "The saved scan could not be read; scanning the whole repository."
3. format != FORMAT, or code != `_code_signature()`, or the code is "": code cache.other_version, "The saved scan was made by a different version of this app; scanning the whole repository."
4. repo_root differs: code cache.other_copy, "The saved scan belongs to another copy of the repository; scanning the whole repository."
5. Compute the current fingerprint. If either side is not `complete: true`: code cache.incomplete, "Could not check every library file for changes; scanning the whole repository."
6. kicad part differs: code cache.kicad_changed, "The KiCad footprint folder changed since the saved scan; scanning the whole repository."
7. custom_git differs: code cache.custom_commit, "The Custom library was committed or switched to another version since the saved scan; scanning the whole repository."
8. files or folders differ: code cache.stale. n counts the added, removed and changed keys across files and folders. The text is "1 library file changed since the saved scan; scanning the whole repository." or "<n> library files changed since the saved scan; scanning the whole repository."
9. Decode the result. A decode error is cache.unreadable. Every SymbolLibrary.rel_path must be a key of the current `files`, and every FootprintLibrary.rel_path must be in the current `folders`. Every collision_peers entry must be in either. Otherwise the note is cache.unreadable.
10. Otherwise: code cache.reused, "Showing the saved scan from <saved_at as YYYY-MM-DD HH:MM>: no library file changed since then. Use Rescan for a full scan."
CacheCheck.fingerprint carries the current fingerprint whenever step 5 ran, so the worker does not walk twice.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| saved scan file -> app | `%APPDATA%/KiCadExtLibManager/scan_cache/*.json` is read back at startup. It may be corrupt, truncated, from another app version, or edited by hand, so it is untrusted input. |
| repo working tree / Custom .git files -> fingerprint | File stats and small git files (HEAD, refs, packed-refs) are read to decide freshness. A wrong verdict would show old data. |
| GUI thread <-> worker thread | The worker deep-copies the ScanResult that the GUI keeps toggling `selected` on. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-gg7-01 | Tampering | scan_cache.load_fresh / decode_result | low | mitigate | JSON only (no pickle or eval), a 64 MB read cap, and a strict per-type decode that raises on any wrong type, missing key, unknown severity or status. Every library rel_path must be a file or folder the freshness check just saw. Any failure gives cache.unreadable and a full scan. Atomic fixes keep their existing `_inside(..., "Custom")` guard, so a tampered FixSpec path still cannot write outside Custom/. |
| T-gg7-02 | Spoofing (stale data presented as current) | scan_cache.fingerprint / update_library | medium | mitigate | The fingerprint covers every scanner input: library files, .pretty folders, Custom/3DModels, Custom .gitignore, Custom HEAD, the KiCad folder and the app code hash. An incomplete fingerprint is never fresh. Stats are taken before the scan reads the files. update_library refreshes only the rescanned library's keys, so any other change still forces a full scan. Tests pin the fingerprint against the scanner's own file lists. |
| T-gg7-03 | Denial of Service | load_fresh / app start | low | mitigate | Oversized or garbage files fall back to a full scan. Every cache step in the worker is wrapped so a cache error can never stop the scan or crash the start. |
| T-gg7-04 | Tampering | scan_cache.save | low | mitigate | It writes through fsutil.atomic_write_text (same-folder temp file plus os.replace), so a crash never leaves a half-written cache. A failed write gives one WARNING and the scan result is still shown. |
| T-gg7-05 | Information Disclosure / Elevation | _custom_git_state ref path | low | mitigate | The ref name from HEAD must start with `refs/` and contain no `..` part before it is used as a path; it is read-only access. |
| T-gg7-06 | Tampering | settings.scan_cache_file | low | mitigate | The path is derived from the QSettings INI folder, outside the repo and Custom/, with one file per repo root hash. A test asserts the path is not inside the repo. |
| T-gg7-07 | Tampering (race) | rescan_library deep copy vs GUI clicks | low | accept | Under the GIL a deep copy of bool flags is safe. The live selection is re-applied on the GUI thread after the worker ends, so a stale snapshot flag never reaches the trees. |
| T-gg7-SC | Tampering | npm/pip/cargo installs | low | accept | No package is installed: the change is stdlib only (json, hashlib, os, functools, datetime). |
